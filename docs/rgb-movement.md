# 移动彩光

2026-10-28，RGB-MOVE2。用户确认 RGB-STABLE 在连续 WASD 下仍明显闪烁，上一轮静止放灯及离散位置移动不能作为连续移动验收。

## 原因

原静态体素通过顶点 imageAtomicMax 写入 R32UI shadowcolor1，但这张纹理同时仍是阴影 FBO 的颜色附件。对本机 J9 的检查发现，原生阴影绘制会恢复 FBO 默认 draw buffers，普通阴影片元可能覆盖这个附件。删除多余的片元输出声明不能保证已启用附件保留原值。

读回中的 0x3f0a8a8b 无法由体素材质打包函数产生，按 float32 解释却正好是 138/255。多个运行在相同纹理地址重复出现这类浮点颜色位模式。真实墙上火把 (-469,81,727) 曾在存在、消失、恢复之间跳变；楼梯 (-472,85,702) 也曾漏采。CPU 对同帧体素重算的光照和透射与 GPU 一致，说明这些实例的上游采集输入已经错误。

另一个确定的问题是覆盖权重随整数体积原点计算。连续移动跨过整数格时，原点会跳一格，边界权重也会瞬间变化。

## 重构

将原前端 colortex5 的水面和反射用途完整迁到 colortex9，包括格式、清屏、混合和渲染目标映射。固定尺寸 colortex5 专用于整数体素；本机 J9 对固定尺寸普通缓冲槽会从场景 FBO 分离实际纹理，所以默认 draw buffers 无法再覆盖体素。

采集、清空和查询统一使用 colorimg5 的 imageAtomicMax、imageStore 和 imageLoad。J9 会调整场景纹理过滤，整数图不再通过普通 sampler 读取。保留 image 写入到 prepare 查询之间的同步。装配入口统一 GLSL 450，符合当前 Windows 主平台约定。

覆盖权重改为按连续相机坐标计算，并预留一格保护区，保证整数存储原点变化时混合权重连续。GPU 回归在跨格前后测得最大 RGB 差约 1.39e-8。

现有逐灯颜色、遮挡、玻璃透色与 RGB 间接光保留。默认光照和后处理仍采用上轮用户确定的数值。

## 输入测试

新增 seam_village_rgb_wasd 场景，在存档副本村庄 (-458,89,713) 只传送一次，设置创造飞行。预热 25 秒后，通过正式客户端 Tick 输入持续保持 W、D、S、A，每 3 秒换向，共移动 80 秒。后续不设置坐标、旧位置、角度或零速度，移动由原版输入、物理与帧间插值处理。

每个渲染帧记录实际 Camera.position、玩家位置、速度和按键状态。选取移动段中的 3564 帧，所有帧均有相机位移、速度持续非零，四个方向键都有连续保持记录；另有一组连续原生画面供核查。该证据替代之前每半秒设置坐标的移动测试。

## 结果

实际 Renderer 为 NVIDIA GeForce RTX 4060 Laptop GPU，1920×1080、视距 12、High、无配套数据 Mod。

连续移动段 70 次快照、69 组比较中，非法材质和失效源身份均为零，2,479,902 条透射射线独立重算无超差。剔除源和接收点覆盖边界后的 14,546 次固定表面比较，直接 RGB 最大差为零；间接场最大差为 0.000244140625。采集有两次内容变化，均未造成验收范围内的直接光跳变，未重新出现普通阴影浮点值覆盖整数体素。

此前独立存储的旋转、离散移动和编辑回归共 118 次快照也没有非法材质，旧火把、楼梯和相邻圆石保持正确。首次场景加载时仍记录到少量真实几何补入，不能据此宣称每帧从启动起完全不变。

四档和独立彩光开关的八组合通过资源契约与编译检查。真实输入测试有数据读回和截图开销，不用于宣称独立帧率。

## 交付

完整来源、逐帧相机 CSV、原生图像、读回与独立检查保存在 local-docs/migration/checkpoints/RGB-MOVE2。部署前备份真实实例旧包和设置，部署后逐文件比较哈希。部署时间和备份位置以 deployment.json 为准。

## 边界

一格体素、每格三个候选与有限体积仍是当前近似。覆盖范围外保留普通方块照明；真实区块或几何更新仍会改变光照。本轮解决数据覆盖和跨格权重跳变，验收范围为上述开放村庄连续输入路径，不扩张为所有存档和资源包保证。
