# 04 · 光照模型

> 对照代码读：[`lib/lighting.glsl`](../shaders/lib/lighting.glsl)。
> 这一章的目标：让你能看着自己屏幕上的画面，说出"这里为什么是这个亮度"。

---

## 1. 光照的基本框架

所有光照模型都是同一个式子的不同实现：

```
最终颜色 = 反照率(albedo) × 光照(lighting)

           ↑                   ↑
      表面本身是什么颜色    有多少光落在它上面
```

**把这两件事彻底分开**是渲染的第一原则。它的好处是：

- 换贴图不需要动光照代码
- 换光照不需要动贴图
- 想加新光源（萤石、闪电、极光）只是往"光照"这一项里加东西

本项目 `computeLighting()` 的完整公式：

```
颜色 = albedo × 环境光(光照贴图)                    ← 间接光
     + albedo × 阳光颜色 × (N·L) × 阴影系数          ← 直接光
     + albedo × 极暗的天空光补偿                     ← 防止纯黑
```

## 2. 环境光：直接"偷" Minecraft 的光照贴图

### 光照贴图是什么

Minecraft 给每个方块位置算好了"这里有多亮"，烘焙进一张 16×16 的小图
（`lightmap`）。它的两个轴是：

```
        y = 天空光等级 (0~15)
        ↑
   15   │                    ← 露天正午：最亮
        │
        │
    0   │
        └──────────────────→ x = 方块光等级 (0~15)
            ↑ 火把旁边：橙色暖光
```

采样它就能直接得到：
- 火把旁边是**暖橙色**
- 露天正午是**白色**
- 洞穴深处是**接近黑色**
- 月光下是**偏冷的淡蓝**

```glsl
vec3 lmColor = texture2D(lightmap, lmCoord).rgb;
vec3 ambient = albedo * lmColor;
```

### 为什么这样很好

如果你从零实现"点光源 + 衰减 + 阴影"，会写几百行代码；
而 MC 已经把这个结果烘焙好了，一次纹理采样就拿到，
**开销几乎为零，观感还天然符合玩家的预期**。

所以本项目的策略是：**环境光完全交给光照贴图**，
自己的光照计算只负责"光照贴图表达不了的东西" —— 也就是
方向性的太阳光和它投下的阴影。

### 它的局限

- **不随光源移动实时更新**：光照贴图是 MC 每帧重新算的，
  但它是"体素级"的，无法表达精细的明暗过渡
- **没有色彩饱和**：强光下应该是白色，光照贴图只会给到灰色
- **无法区分光源颜色**：所有方块光都是同一个暖色

想突破这些限制，就要用到 SSAO、光线追踪等进阶方案
（见 [`08-扩展指南.md`](08-扩展指南.md)）。

## 3. 直射光：Lambert 漫反射

### N·L：整个光照模型的基石

```glsl
float NdotL = clamp(dot(normalView, lightDirView), 0.0, 1.0);
vec3 direct = albedo * lightColor * NdotL * shadow;
```

**点积的几何含义**：`dot(A, B) = |A| × |B| × cos(θ)`。
两个单位向量的点积**就是夹角的余弦**。

```
        ☀ 太阳
         \
          \  θ
           \
    ────────┴──────── 表面
     N 朝上

  θ = 0°   光垂直照射   cos = 1.0   最亮
  θ = 45°  斜射         cos ≈ 0.71  亮度的 71%
  θ = 90°  平行掠过     cos = 0     不亮
  θ > 90°  从背后照     cos < 0     → clamp 到 0
```

**为什么要 `clamp` 到 0？**
点积为负意味着光从背面来。不 clamp 的话会得到"负光照"，
表面会比全黑还黑，颜色会变成奇怪的负数值（进而在 gamma 运算里变成 NaN）。

### 为什么亮度正好等于 cos θ

这是 Lambert 余弦定律的物理含义：
一束横截面积为 A 的光，斜着照到表面上时覆盖的面积是 `A / cos θ`。
同样的光摊到更大的面积上，单位面积的亮度就下降到 `cos θ` 倍。

所以 Lambert 不是"一种近似"，它就是漫反射的物理正确解。

### 光源方向怎么来

```glsl
vec3 sunDir = normalize(sunPosition);
vec3 moonDir = normalize(moonPosition);
float sunNdotL = max(dot(normalView, sunDir), 0.0);
float moonNdotL = max(dot(normalView, moonDir), 0.0);
```

- `sunPosition` / `moonPosition` 是**视图空间**的方向（长度约 100）
- 两个方向分别参与直射光计算，再用昼夜权重渐变
- 太阳与月亮几乎相反，直接插值其方向会在黄昏附近抵消

### 昼夜颜色怎么算

```glsl
float getDayFactor() {
    return smoothstep(-0.12, 0.16, getSunHeight());
}
```

`getSunHeight()` 是太阳相对**世界地平线**的高度（`-1` 到 `1`）。
注意它必须从**世界空间**算：

```glsl
vec3 getSunDirWorld() {
    return normalize(mat3(gbufferModelViewInverse) * sunPosition);
}
```

如果直接用视图空间的 `sunPosition.y`，那么**玩家一低头，太阳的高度就变了**，
整个世界的亮度会随着视角闪动 —— 这是个很典型的错误。

颜色：

```glsl
vec3 sunColor = mix(sunsetColor, noonColor, smoothstep(0.0, 0.30, sunHeight));
```

- 太阳高度 `0`（地平线）：`(1.0, 0.48, 0.20)` 橙红色 —— 瑞利散射
- 太阳高度 `> 0.3`（高挂）：`(1.0, 0.97, 0.92)` 接近白色

物理原因：太阳低时，阳光要穿过更厚的大气，**波长短的蓝光被散射掉**，
剩下来的偏红。这就是日出日落是红色的原因。

## 4. 阴影：不是"颜色变暗"，而是"少了一项"

本项目里阴影的做法：

```glsl
vec3 direct = albedo * lightColor * NdotL * shadow;   // shadow ∈ [0,1]
```

`shadow = 0` 时直射项完全消失，但**环境光还在**。
所以阴影里的东西不是纯黑，而是"只剩环境光"的样子 —— 这才是真实的。

这也是新手最常见的错误：把阴影实现成 `color *= 0.5`。
那样阴影里外只有亮度差别，没有色温差别，看起来就很假。

详细实现见 [`05-阴影映射.md`](05-阴影映射.md)。

## 5. 高光：Blinn-Phong

水面、冰、金属需要"镜面反射"才有质感。本项目用最简单的 Blinn-Phong：

```glsl
vec3 viewDir = normalize(-viewPos);              // 表面指向摄像机
vec3 halfDir = normalize(lightDirView + viewDir); // 光线与视线的角平分线
float NdotH = clamp(dot(normalView, halfDir), 0.0, 1.0);
vec3 specular = specularColor * pow(NdotH, glossiness);
```

### 为什么用"半程向量"

原始 Phong 模型算的是 `dot(reflect(-L, N), V)`，需要一次 `reflect`。
Blinn 的改进是**算 L 和 V 的角平分线**：

```
       L   H   V
        \  |  /
         \ | /
    ──────\─┴─/──────  表面
              N

   H 与 N 越接近共线，高光越强
```

数学上 `pow(N·H, n)` 和 `pow(R·V, n)` 效果相近，
但**省掉一次反射计算**，而且在掠射角下不会出现高光断裂。
这就是它成为业界默认选择的原因。

### `glossiness` 怎么调

| 值 | 效果 | 适用 |
|---|------|------|
| 20 ~ 50 | 大面积糊开的亮斑 | 潮湿的石头 |
| 100 ~ 300 | 明确的圆形高光 | 水面 |
| 1000+ | 锐利的针尖状高光 | 抛光金属 |

本项目的 `gbuffers_water.fsh` 用 `300.0`，可以自己改着感受一下。

### ⚠️ 高光也必须乘阴影系数

```glsl
color += specular * shadow * getDayFactor() * 0.8;
```

被遮住的地方不可能有太阳的镜面反射。
漏掉 `shadow` 的话，阴影里的水面会出现一块凭空出现的亮斑。

## 6. 完整的 `computeLighting()`

把上面几项拼起来（对应 `lib/lighting.glsl`）：

```glsl
vec3 computeLighting(vec3 albedo, vec3 normalView, vec3 lmColor,
                     vec2 lmCoord, float shadowFactor) {
    float NdotL = clamp(dot(normalView, getLightDirView()), 0.0, 1.0);

    // ① 间接光：来自光照贴图（火把、天空散射）
    vec3 ambient = albedo * getAmbientColor(lmColor);

    // ② 直接光：太阳/月亮，被阴影衰减
    vec3 direct  = albedo * getLightColor() * NdotL * shadowFactor;

    // ③ 保底亮度：完全封闭的洞穴里也要能看见轮廓
    vec3 minimum = albedo * vec3(0.02, 0.025, 0.035) * lmCoord.y;

    return ambient + direct + minimum;
}
```

每一项都可以单独调：

| 想改什么 | 改哪里 |
|---------|-------|
| 整体太暗/太亮 | `settings.glsl` 的 `AMBIENT_STRENGTH` / `SUNLIGHT_STRENGTH` |
| 环境光颜色太艳 | `SKY_TINT`（0 = 全用光照贴图色，1 = 全用天空色） |
| 夜晚太亮 | `getLightColor()` 里的 `moonColor` 系数 |
| 日出日落不够红 | `getLightColor()` 里的 `sunsetColor` |
| 洞穴里太黑看不见 | `minimumAmbient` 的数值 |

## 7. 如果想更进一步：PBR 简介

本项目是"轻量 PBR 近似"，真正的 PBR 会用**渲染方程**：

```
Lo(p, ωo) = ∫ fr(p, ωi, ωo) · Li(p, ωi) · (n·ωi) dωi
             ↑              ↑            ↑
        材质 BRDF        入射光       Lambert 项
```

实际实现里最常用的分解是 Cook-Torrance：

```
BRDF = 漫反射项 + 镜面项

镜面项 = D(法线分布) × G(几何遮蔽) × F(菲涅尔)
             ↑              ↑            ↑
        微表面朝向分布   微表面互相遮挡  不同角度的反射率
```

- **D（GGX/Trowbridge-Reitz）**：决定高光形状，替换本项目的 `pow(NdotH, n)`
- **G（Smith）**：掠射角时高光不该无限亮，需要遮挡修正
- **F（Schlick 近似）**：`F = F0 + (1-F0) × (1 - V·H)^5`，
  让边缘反射率升高 —— 这是"水面边缘更亮"的原因

**要不要现在就上 PBR？** 不建议。原因：

1. 视觉上限主要受限于"光照信息来源"（光照贴图太粗糙），
   不是受限于 BRDF 精度；
2. PBR 需要"粗糙度/金属度"这些材质参数，
   而 MC 的贴图里没有，得靠你自己的材质表（`block.properties`）提供；
3. 本项目的结构已经为此准备好了 —— **替换 `computeLighting()`
   一个函数即可，其余代码一行不用改**。

## 8. 动手实验

改这几处，进游戏看差别（`F3 + R` 重载）：

```glsl
// 实验 1：把环境光全部关掉，只剩直射光（会得到非常硬核的画面）
return direct;   // 在 computeLighting 末尾返回

// 实验 2：让太阳从正上方照下来（把光源方向改成常量）
vec3 lightDirView = vec3(0.0, 1.0, 0.0);   // 视图空间的正上方

// 实验 3：阴影系数改成 1.0，看看"没有阴影的世界"是什么样
float shadow = 1.0;

// 实验 4：把 NdotL 换成 1.0，去掉明暗过渡（只剩纯色 + 阴影）
float NdotL = 1.0;
```

**每次只改一处**。改多了就分不清哪个变量造成了什么变化 ——
这是调试光影最重要的一条纪律。
