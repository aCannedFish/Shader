# 彩色光照

0.2.0 为发光方块提供不同光色，并让染色玻璃过滤照明。Shader 与配套 Mod 使用新版数据布局，需要同时更新并完整重启客户端。只有 Shader 时保留原版暖色方块光和日月玻璃滤色。

## 光照场

Minecraft 的原版方块光贴图只有标量传播等级。当前实现保留这套基础传播与墙体遮挡，再用色相体积恢复各光源的颜色，用独立点光阴影修正可见度，并单独累加局部 GI。没有可用配套数据时回退原版光照。

`HueVolume` 按发光颜色与等级分组，使用原版遮光等级和完整面遮挡规则进行六邻域传播。每格存辐射加权的平均色相及发光等级；Shader 由原版接收等级和已知发光等级推算有效距离，避免灵魂火把、红石火把等弱光源近场过暗。相邻光色在接收面内插值，只有有光格参与，减轻颜色按方块跳变。

色相体积覆盖随相机分段移动的 256×128×256 方块区域。Shader 在水平距离 80～96 格、垂直距离 32～48 格间渐退为原版色调；光源自身的传播范围不扩大。单色 8³ 小块直接存于索引表，混色小块使用最多 2048 个稳定池槽，只有变化数据上传。混色块超出预算时优先保留近处结果。

客户端只复制需要的区段状态，传播在单独工作线程运行。周围半径 6 格的方块编辑会触发优先更新；其他区段和光源分批扫描，未捕获的遮挡变化由周期性刷新补齐。新发现的光源、区块加载与复杂传播仍可能有延迟。

## 光源

`LightMaterials.java` 定义发光颜色，先从显示 RGB 转到线性空间。关闭的红石火把、熄灭的灯等状态不会作为光源。发光材质自身的贴图与发出光色分别处理。

| 光源 | 光色 |
| --- | --- |
| 火把、灯笼、蜡烛 | 淡黄色 |
| 灵魂火把、灵魂灯笼、灵魂火焰 | 蓝色 |
| 红石火把 | 红色 |
| 海晶灯、信标、光源方块 | 白色 |
| 荧石、红石灯 | 暖黄色 |
| 菌光体、南瓜灯 | 橙黄色 |
| 熔岩、岩浆块 | 橙红色 |
| 末地烛 | 偏暖白色 |
| 紫晶、哭泣的黑曜石、重生锚 | 紫色 |
| 三种蛙明灯 | 对应的黄、绿、紫色 |
| 铜火把与铜火焰 | 青绿色 |

其他发光方块使用偏暖白色回退。关闭 `ENABLE_COLOURED_LIGHTING` 后使用原版暖色方块光和中性滤色阴影，局部阴影及 GI 仍由各自设置控制。

## 点光阴影

按相机距离与光源影响半径选择有限数量的活动光源，默认上限为 32。每个光源保存六面距离阴影图，围绕自身采集已加载方块的形状，跳过源方块自身；点光阴影不再依附相机周围的 GI 快照。

持续被选中的光源保留槽位和阴影图，新增、移除时约用 0.4 秒淡入淡出。近处编辑优先重绘相关光源，远处遮挡约每 4 秒重新检查，执行量仍受每帧更新预算限制。未被选中的光源继续保留原版传播光，不具有独立阴影图。

阴影只移除选中光源能够解释的光照份额，避免一个被遮挡光源把其他可见光源一起压暗。这里保留了原版各光源取最大传播等级的性质，无法从标量贴图严格还原每个光源的能量贡献。

## 玻璃透射

局部点光和 GI 使用分通道 Beer–Lambert 吸收：`T = exp(-Σ σₐ × 路径长度)`。光路通过 DDA 划分格子并积累吸收，玻璃板按中央细柱和连接臂求交，多层透射率相乘。透明玻璃不染色，遮光玻璃仍遮挡。

六面图集的 R 通道存不透明深度，G 通道存第一层玻璃深度，用于避免给玻璃前的接收面染色。接收位置相关的 RGB 透射缓存放在图集尾部，受相机周围 GI 体积范围限制，边缘渐退。GI 注入和跨格传播也考虑吸收。

日月表面阴影由 Shader 的 `shadowcolor0` 记录最近投影体的类别和颜色，并结合 `shadowtex1` 排除后方不透明遮挡。彩色玻璃提供经验透射色，发光体投影使用距离衰减补光。这是最近一层近似，无法准确累积多层日月玻璃吸收；发光投影补光也不等同于独立点光求解。空气与水下体积散射尚未逐点采用玻璃染色。

## 坐标与接口

OptiFine J9 使用浮动相机原点。CPU 方块快照保持绝对坐标，上传 Shader 的直射、GI 与色相原点减去加载器的 `cameraOffsetX/Z`；偏移改变时刷新程序 uniform，避免跨千格移动后照明错位。

配套纹理使用单元 12、14，天空噪声使用单元 15。Shader 检查布局版本，旧 Mod 不满足本版布局时回退原版光照。透明绘制前补齐场景与不透明副本的天空，避免染色玻璃写深度后露出黑色背景。

## 设置

彩色光照开关位于“光照”页；活动光源数、半径、独立阴影质量与更新数位于“局部光照”页，GI 体积、反弹和传播预算位于 GI 页。低、中、高、极高预设会一起调整主要成本选项，完整数值见[配置说明](configuration.md)。

升级时同时替换 Shader ZIP 与 Mod JAR，移除旧 Mod 后完全重启；F3+R 不能载入新的 Java 实现。旧的同名光影设置文件仍可能覆盖源码默认值。

## 验证

0.2.0 发布检查包含当时默认及四档预设的 42 个 Shader 入口、关闭相关功能的分支、配套 GPU 程序、Java 21 编译目标、86 项配置与发布附件校验。0.2.1 的新增优化与验证见[管线优化](25-pipeline-optimization.md)。

早期开发曾执行固定灯位、玻璃前后、多层玻璃、跨浮动原点和远近光源的真实客户端采集与 GPU 重放。2026-10-16 本地 `.preview` 资料被清理；这些历史结果不能作为最新色相传播、阴影调度与预设的视觉验证。本次发布未重新采集游戏画面，也没有新的帧率测量。

仓库保留 `verify-colour`、`verify-colour-origin` 和 `verify-colour-range` 检查入口。重新使用前需要重建预览环境并核对探针与新版图集布局，旧版数据断言不能直接视作本版保证。

## 来源

- Pharr、Jakob 与 Humphreys，[PBRT 第 4 版，Transmittance](https://pbr-book.org/4ed/Volume_Scattering/Transmittance)：按光路积分消光、分段透射率相乘与能量约束。
- Amanatides 与 Woo，1987，[A Fast Voxel Traversal Algorithm for Ray Tracing](https://www.cse.yorku.ca/~amana/research/grid.pdf)，[Eurographics 原始出版记录](https://doi.org/10.2312/egtp.19871000)：网格光线遍历。本项目处理了负方向、平行轴与同时跨越多个边界的情况。
- McGuire 与 Enderton，2011，[Colored Stochastic Shadow Maps 原文](https://research.nvidia.com/sites/default/files/pubs/2011-02_Colored-Stochastic-Shadow/McGuireI3D11Shadows.pdf)：覆盖率与 RGB 透射率的区别、多层半透明阴影及其过滤代价。本实现没有采用其中的随机丢弃算法。
- Kaplanyan 与 Dachsbacher，2010，[Cascaded Light Propagation Volumes for Real-time Indirect Illumination 原文](https://cg.ivd.kit.edu/publications/p2010/CLPVFRII_Kaplanyan_2010/CLPVFRII_Kaplanyan_2010.pdf)：低阶球谐光传播与局部体积的工程思路。当前沿用项目已有的单层局部 GI，没有实现论文的级联结构。
