# 彩色光照

本机开发实现为原版发光方块配置不同光色，并让染色玻璃过滤直射与间接光。光源数据和玻璃材质由配套 Mod 从当前客户端方块状态采集，Shader 负责表面照明和显示。需要同时更新光影与配套 Mod，完整重启客户端后生效。

## 方案

现有原版光照贴图只提供标量方块光，无法判断亮度来自火把、灵魂火把还是其他方块。本实现继续使用配套 Mod 的独立点光源与六面阴影，在线性 RGB 中累加不同光源的辐射。

玻璃透射按分通道 Beer–Lambert 衰减计算：`T = exp(-Σ σₐ × 路径长度)`。多层玻璃的透射率相乘，任何通道的透光率均在 0～1 之间。颜色不会覆盖已有光色，也不会增加光能。

调研对比了普通单层彩色阴影图、Colored Stochastic Shadow Maps 与体素光路积分。单层颜色无法正确区分玻璃前后的接收物，多层也容易丢失；随机彩色阴影需要额外过滤噪声。本项目利用已有方块快照进行确定性的 DDA 遍历，并将每个光源到不同接收位置的 RGB 透射率缓存起来。

## 坐标

OptiFine J9 的 `cameraPosition` 使用浮动原点：进入世界或大幅移动时，将 X/Z 的千格偏移单独保存。Mod 的方块快照仍使用 Minecraft 绝对世界坐标，因此上传直射与 GI 原点时必须减去相同的 `cameraOffsetX/Z`。

此前未做这一步，在 X≈1757 的玩家位置，Shader 使用的相机 X≈757，Mod 却传入 X≈1740 的体积原点，相机被错误地计算到体积外约 983 格处，整个局部照明回退为原版暖光。原先 X≈220 的测试房间不会触发这个错误。

当前保留 CPU 快照的绝对坐标，只把上传的直射与 GI 原点转换到加载器坐标系。加载器原点变化时立即刷新所有程序的相关 uniform，避免沿用上一个坐标系的缓存。光源配色、亮度、半径及用户配置不参与这次修复。

新增七个真实客户端回归：原点附近、正负 X、跨千格 Z、远处红玻璃日光，以及截图坐标附近的草地和石英接收面。GPU 读回确认相机处于正确的局部体积中，平移相同房间后的平均显示通道差低于 0.36；七个原生截图与 GPU 重放逐像素一致。检查命令为 `python3 tools/preview.py verify-colour-origin`，对照图和数据位于 `.preview/coloured-origin-review/`。

## 光源

`LightMaterials.java` 统一定义光色。配色先以显示 RGB 编写，再转换到与 Shader 一致的线性空间；发光等级继续决定能量与半径。关闭的红石火把、熄灭的灯和其他不发光状态不会被当作有效光源。

| 光源 | 光色 |
|---|---|
| 火把、灯笼、蜡烛 | 淡黄色 |
| 灵魂火把、灵魂灯笼、灵魂火焰 | 蓝色 |
| 红石火把 | 红色 |
| 海晶灯、信标、光源方块 | 白色 |
| 荧石、红石灯 | 暖黄色 |
| 菌光体、南瓜灯 | 橙黄色 |
| 熔岩、岩浆块 | 橙红色 |
| 末地烛 | 偏暖白色 |
| 紫晶、哭泣的黑曜石、重生锚 | 紫色 |
| 三种蛙明灯 | 对应的黄、绿、紫色 |
| 铜火把与铜火焰 | 青绿色 |

其他发光方块使用偏暖白色回退。发光材质自身的贴图与发出的光色分别处理，海晶灯贴图带青色边框不会使它的照明变成蓝光。

## 透射

支持全部 16 色染色玻璃与玻璃板。颜色来自方块染料，并保留灰、白、黑玻璃的中性色衰减。透明玻璃不染色；遮光玻璃仍按不透明遮挡处理。

DDA 精确划分光线经过的格子区间，并按实际长度积累吸收。玻璃板拆为中央细柱和连接臂，按 1/8 方块的实际形状求交；以名义厚度校准吸收，使正向穿过玻璃板也有可辨认的滤色，斜向路径则衰减更多。

六面阴影图的 R 通道继续存不透明深度，G 通道单独存第一层染色玻璃深度，避免把玻璃前的物体染色。RGB 透射体积存于同一图集尾部，每个光源保留带边界的切片；表面只需两次过滤采样重建三维透射率，不逐像素遍历整条光路。

日月光另保留一个方向光透射体积。在局部快照的有效范围内，透明玻璃的太阳遮挡由 RGB 透射代替；普通不透明阴影继续使用原有方向光阴影图。直接受光表面和 GI 注入使用相同透射率，GI 传播经过玻璃时也按通道衰减。

## 透明

透明材质绘制前，`deferred1` 同时为场景颜色和水体用的不透明副本补入天空。原先只有副本包含天空，场景颜色仍是黑色；染色玻璃写入深度后，后续天空阶段跳过这些像素，导致天空天窗显示为不透明的暗红实面。透明玻璃中央 alpha 为零，会被丢弃，因此未暴露同样的问题。

现在玻璃先与有效天空混合，之后保留原有透明度、材质光照与 RGB 光源吸收。回归包括透明、红色、蓝色天窗，以及正式存档副本中 X≈1713、Y≈69、Z≈−118 的原有测试房间；没有修改正式存档。

## 范围

近处保留默认边长 32 方块、最多 32 个活动点光源的精细阴影与 GI。远处的光色采集独立于这个体积：扫描已加载区块的发光材质，水平半径随视距在 64～128 格之间，垂直检查相机上下各 48 格，保留最多 128 个相关光源。

体积外沿用 Minecraft 的方块光传播等级和遮挡，用相关光源的线性 RGB 混合恢复光色，再连续过渡到近处的独立阴影和 GI。光源影响半径没有被扩大。这解决了接收物必须进入相机周围很小的体积才会从暖光变为彩光的问题。

广域结果按区段保留，逐批更新时不清空已有颜色；没有发光材质的调色板直接跳过，表面方块光为零时也跳过广域光色查询。已知光源发生开关或材质变化时，优先刷新所属区段。近处 32³ 快照由原来八批缩为两批；新直射数据只等待必要的阴影计算，不等待全部 GI。相同场景不再周期性清空阴影图或重启尚未完成的 GI。

远处颜色属于原版标量光场上的色相近似，复杂遮挡中不能严格分离每个光源的传播贡献。精确的 RGB 玻璃透射和独立阴影仍受近处体积范围限制；新发现的远处光源、尚未加载的区块和超过数量预算的光源仍受扫描和选择预算影响。

透射是按世界网格缓存的直线吸收近似，没有模拟光线弯折、玻璃焦散或完整光谱。粗网格会软化小于一格的滤色边界，方块变化需要等待快照更新。当前没有把玻璃染色应用到空气和水下体积散射的每个积分点。

新增 `verify-colour-range` 检查 48、24、8 格的同一光源：前两个位置的光源坐标位于 GI 体积外，仍保留蓝色照明。仰视三种玻璃均可见太阳；正式存档副本的原有小天窗也能透视天空，红玻璃对日光的 RGB 衰减继续通过检查。九个首轮原生画面、五个广域与实时切色画面，以及原房间和切色的后续采集均通过 GPU 重放一致性检查。测试图片和原生 GPU 探针保存在 `.preview/colour-range-review/`。

广域光源的蓝光切红光测试中，首次版本从客户端看到方块变化到 GPU 色相数据变化约为 1214 毫秒。优先检查已知光源后，首次检查方块与 GPU 时已同时看到新状态；采集器以约 100 毫秒间隔检查，这表示在当前采样分辨率内没有观察到额外等待，不能解释为真实延迟等于零。这个测试测量光色数据更新，不等同于整帧性能或完整 GI 的收敛时间。

对外仍只使用纹理单元 13、14。默认设置下增加的透射图集、对应深度空间和吸收纹理约为 15 MiB，具体分配取决于驱动；更新开销随活动光源数和体积大小增长，没有据采集限帧推断游戏 FPS。

## 验证

固定场景包含四种光源、无光基准、透明玻璃、红/蓝玻璃、双层与混色玻璃、玻璃板、不透明墙、三种日光屋顶以及村庄昼夜。正式存档不接受测试命令，场景均在独立副本中建立。

采集器同时记录正常截图和实际 GPU 读回值。透射探针分别放在玻璃前后，避免将玻璃表面本身的颜色误当作照明变化。

```bash
python3 tools/preview.py verify-colour
```

该检查要求火把偏暖、灵魂火把偏蓝、红石火把偏红、海晶灯的 RGB 能量一致；玻璃前透光率为 1，玻璃后发生分通道衰减；双层与混色玻璃分别满足相乘关系；玻璃板不会被漏掉或当成完整实心方块。还检查中性地面的光色和玻璃不在画面中的日光投色。

当前实测红玻璃后的透光率约为 `(0.750, 0.162, 0.141)`，双层为 `(0.563, 0.026, 0.020)`，蓝玻璃后约为 `(0.207, 0.235, 0.736)`；前方探针均为 `(1,1,1)`。这些是当前固定灯位与光路下的线性透射率，不是所有角度的材质常量。

42 个主光影入口、6 个配套 Mod 片元程序编译通过，81 项配置校验通过。17 个原生截图与 GPU 重放逐像素一致。关闭接收面 RGB 透射的同帧对照中，透明玻璃区域差异为 0，红/蓝玻璃后的地面平均通道差为 10.805、8.315，日光接收区域为 22.450、25.226；统计区域不包含可见的玻璃表面。记录位于 `.preview/coloured-verification/`。

## 运行

本次没有修改已发布的 0.1.4 Release。源代码和本机配套 JAR 属于开发版本，光影的 81 项默认配置保持不变。替换旧 JAR 时需要保留备份，并确保 `mods/` 中只有一个 `simpleshader_lighting` 模块；只按 F3+R 无法载入新的 Java 光源与材质代码。

## 来源

- Pharr、Jakob 与 Humphreys，[PBRT 第 4 版，Transmittance](https://pbr-book.org/4ed/Volume_Scattering/Transmittance)：按光路积分消光、分段透射率相乘与能量约束。
- Amanatides 与 Woo，1987，[A Fast Voxel Traversal Algorithm for Ray Tracing](https://www.cse.yorku.ca/~amana/research/grid.pdf)，[Eurographics 原始出版记录](https://doi.org/10.2312/egtp.19871000)：网格光线遍历。本项目处理了负方向、平行轴与同时跨越多个边界的情况。
- McGuire 与 Enderton，2011，[Colored Stochastic Shadow Maps 原文](https://research.nvidia.com/sites/default/files/pubs/2011-02_Colored-Stochastic-Shadow/McGuireI3D11Shadows.pdf)：覆盖率与 RGB 透射率的区别、多层半透明阴影及其过滤代价。本实现没有采用其中的随机丢弃算法。
- Kaplanyan 与 Dachsbacher，2010，[Cascaded Light Propagation Volumes for Real-time Indirect Illumination 原文](https://cg.ivd.kit.edu/publications/p2010/CLPVFRII_Kaplanyan_2010/CLPVFRII_Kaplanyan_2010.pdf)：低阶球谐光传播与局部体积的工程思路。当前沿用项目已有的单层局部 GI，没有实现论文的级联结构。
