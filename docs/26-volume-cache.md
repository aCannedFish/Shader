# 体积缓存

本轮保留三项改动：可选的四分之一分辨率体积场、天空与云环境的周期接缝修复，以及水下合成的重复计算清理。天空缓存仍沿用原来的通道布局，没有增加绘制通道或颜色附件。

## 体积档位

“世界”页面新增 `VOLUMETRIC_RESOLUTION`：

| 值 | 内部视口 | 用途 |
| --- | --- | --- |
| 0 | 场景宽高的四分之一 | 低开销，体积片元数约为默认的 1/4 |
| 1 | 场景宽高的二分之一 | 默认，保留更多云与光束细节 |

该选项同时控制体积云、空气日光散射和水下光柱。生成与深度感知重建共用 `volumeSize()`，对内部尺寸取整，避免奇数宽高时读写区域不一致。低预设使用四分之一，其余预设保持二分之一。

场景颜色、几何、纹理和水上景物折射仍使用原来的场景尺寸，降低的是体积场本身的采样密度。重建继续拒绝前景两侧不相容的深度；云的细小结构和窄光束会变粗，这是低档明确接受的质量取舍。当前没有通过时间累计补回低分辨率细节。

修改此项会改变加载器视口，离线预览必须重新采集。普通算法与颜色修改仍可在匹配视口的记录上重放。

## 天空接缝

天空和云环境位于 `colortex3` 的局部区域，右侧还存有云影。旧查询在方位角两端直接钳制，两个端点分别落在不同经线的纹素上，不能保证连续；直接对整个附件使用纹理环绕又会读到旁边的云影区域。

现在 `sampleSkyStrip()` 只在接缝附近显式读取末列和首列并插值，内部位置保留一次硬件过滤读取。天空和云环境共用同一映射，纬度端点与各自的区域偏移保持不变。

实际 GLSL 探针覆盖两个区域、奇数尺寸、单列查找表、南北极和区域外的高亮哨兵。方位角 0 与 1 的输出差异均为 0，未读入相邻区域。纬度方向的误差不超过约 0.00051，来自 RGBA16F 中间存储的精度。

## 水下合成

入水状态是整帧常量。`composite2` 现在直接进入水下光学分支，跳过随后会被覆盖的天空计算、水面元数据读取、空气重建和部分位置反投影。水上分支复用已读取的场景颜色。

这项改动保持水下前景、折射、浑浊度和能见度算法不变，没有新增整屏模糊。对应的同帧对照用于检查工作调度变化是否影响画面。

## GPU 测量

云积分使用仓库实际 `composite` Shader，在 Apple M3 / OpenGL 4.1 上运行。输入为固定的合成密云场、天空深度和独立的空水面元数据，使用 90° 透视相机，尺寸 1280×720，云质量与步数一致。每次实验在同一上下文交替运行两个档位，预热 5 次后各记录 25 个 GPU 时间样本；三组实验交替先后顺序。

| 实验 | 二分之一视口 | 四分之一视口 |
| --- | --- | --- |
| 1 | 2.328 ms | 0.688 ms |
| 2 | 2.354 ms | 0.708 ms |
| 3 | 2.480 ms | 0.750 ms |
| 三组中位数 | 2.354 ms | 0.708 ms |

该测试的云积分时间约减少 70%。参与积分的体积片元数减少约 75%。合成输入为 RGBA32F 常量纹理，中间输出为 RGBA16F；实际游戏噪声是图集，缓存行为与带宽并不相同。这里也不包含重建、天空表、几何、Mod 求解和整帧开销，不能直接换算成游戏 FPS。合成天气与真实世界的云覆盖、观察角度和空区域比例也不同。

## 方案筛选

本轮也尝试过拆出一个额外缓存通道，让云倒影复用已生成的大气表，以及用两个附件在同一通道输出结果、再随体积通道搬运。独立进程的首轮计时曾显示收益，但同上下文交替测试没有支持这个结论：在本机合成模型中，额外通道约慢 10%，双附件方案约慢 20%。这些候选实现已撤回。

这里只能据此判断它们没有足够的本机收益证据，不能推断其它 GPU 一定有相同比例。最终实现保留原有缓存布局，避免把理论计算次数的减少直接当作真实提速。

## 检查

```bash
python3 tools/check_glsl.py
python3 tools/configuration.py --check
python3 tools/check_sky_cache.py
python3 tools/check_volume_quality.py
```

离屏检查不启动 Minecraft。`check_sky_cache.py` 检查实际周期采样函数；`check_volume_quality.py` 使用实际云积分函数与同上下文配对计时。原始数据位于 `.preview/sky-cache-verification/` 和 `.preview/volume-quality-verification/`。

正式场景采用独立存档副本，覆盖天空、云、水面、水下，以及内部 853×480、体积视口 213×120 的非整数比例情况。低档的后续普通镜头会恢复场景渲染倍率为 1，避免把全场景降分辨率与体积档位混在一起。

最终场景检查包含 6 个隔离默认镜头、5 个低档与渲染倍率镜头，以及 3 个启用配套 Mod 的正式默认镜头。对应原生截图与 GPU 重放逐像素一致。正式默认集还确认 Mod 的 GPU 资源和 3 次 GI 反弹已正常发布；将水下调度恢复为旧路径后，天空、水面与水下三幅同帧画面差异均为 0。

44 个主 Shader 入口、7 组配置共 308 次编译和 91 项设置校验通过。日常预览保留最后的正式默认三镜头；质量档位改变时，工具会拒绝直接替换旧记录中的视口。
