# 挂起排查

2026-10-26。用户补充实际进入游戏多次崩溃、当前测试无响应后，暂停功能推进，先保存现场并定位阻塞调用。

## 实际证据

Windows Application记录00:47:55的javaw.exe AppHangB1/1002以及00:55:56的AppHangTransient。实际实例日志停在deferred4加载前后，隔离测试停在composite2加载前后。没有发现对应的新Minecraft crash-report或hs_err文件；这些记录确认挂起，不能解释尚无日志的所有崩溃。所查区间没有显卡4101重置事件，观测显存约1.35GiB，不支持显存耗尽归因。

复现时抓到两类渲染线程栈：

- ShadersCompatibility.remap → String.trim，加载器在CPU上重复处理已现代化的巨大源码。
- GL20C.nglGetProgramiv → Shaders.setupProgram，渲染线程同步等待驱动链接结果。

原始证据保存 `local-docs/migration/windows/hang-20261026/`，检查点归档于 `local-docs/migration/checkpoints/WIN-LOAD/`。第一次抓栈时旧进程已经退出，已保留no-such-process记录；后续PID及有效线程栈均来自当前复现进程。

## 修改

构建器给已现代化的片元和几何程序写入J9识别的兼容完成标记，避免重复转换。写入前扫描并拒绝遗留GLSL语法。203个本机导出阶段比对确认片元/几何没有实际转换；顶点中仍有ftransform及矩阵转换，保留加载器原路径。

仅在MC_GL_VENDOR_NVIDIA条件下，对片元程序设置inline 16及unroll none编译提示。采样预算、计算语句、效果类别、布局及Mod约束不变；这是加载稳定性改动。其他厂商不设置该提示。此入口基于当前J9 pre2本机验证，后续加载器变化需复验。

同时统一光源历史/阴影调度的720720帧循环判断，避免frame0将上一帧误作无效；无效负帧戳继续拒绝。常规原生路径已覆盖，尚未通过完整长时运行跨越循环边界。

测试启动器保存精确子进程PID用于抓栈。新增user_world观察模式，复制用户存档后在原位置运行，不建场景、不传送、不改方块；预热至少60帧后，再要求至少45秒且120帧的输出。
