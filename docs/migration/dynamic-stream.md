# 动态采集

2026-10-26。当前仍为P04.2，精确动态反射未完成。实际实例继续使用WIN-LOAD/a141645；本文件记录隔离原型的生产与交接实现。

## 稳定补测

WIN-LOAD原包完成Windows着色器重载后45.018秒、210帧持续渲染。主世界→下界→末地→主世界四段分别记录220、220、515、205帧，每段超过45秒，正常退出，无编译、链接或OpenGL错误。输出1920×1080、内部1440×810，RTX4060/NVIDIA610.74。证据为windows-native-reload及windows-native-dimensions；这些补测不关闭三维度四档和长期稳定性的全部要求。

## 实现

原生shadow几何阶段的调用零使用RGBA16F原子计数，为实际提交的动态三角形分配记录。C5临时保存位置、UV、三个顶点的染色和原版光照、材质编号、帧号及纹理尺寸。1024记录容量内计数保持精确；溢出单独标记。

J9会在shadow与prepare之间清理场景附件。原型关闭C1/C5自动清理，在prepare读取后通过两个独立场景尺寸绘制恢复双方缓冲：C1白色、C5零。固定尺寸C6单独写入；prepare1整体复制保证控制字段在双方缓冲一致。没有新增颜色附件或由测试助手上传世界数据。

首条记录以四字节编码发布到C6的保留头部区域，完整保留float位。该区域只用于本原型接口检查，不能充当最终全量三角形缓存。初始化、发布和清理都由GPU完成。

## 原生证据

windows-dynamic-stream-v5的末影箱和未激活喷涌核心场景采集48个三角形，无溢出。首条记录来自末影箱锁扣，材质9376、纹理512×256、三角形双倍面积0.015625；UV有效、帧号369与发布一致、两个C6副本一致。627个阶段、309/309图形链接、6/6 compute链接通过。

v1暴露临时数据被自动清理；v2未同步新控制字段到双方持久副本；v3修复生命周期与发布，v4增加纹理尺寸。离线检查又发现450几何阶段与330顶点阶段的gl_PerVertex成员不匹配，v5统一shadow顶点/几何版本后通过链接。失败记录保留，未部署失败版本。

普通包与原型的同场景、30秒预热画面均保留，粒子和动画时间不同，不能宣称逐像素一致。静止主体未发现先前短预热对照中怀疑的独有大块差异。
