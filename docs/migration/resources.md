# 资源约定

## 状态

这是 P02 的资源与精度合同，消费者尚未迁移。分配和驱动验证不代表渲染功能完成。

持久图集与原始采集图集由 `tools/migration_layout.py` 生成。区域含一像素保护边界，生产者和消费者使用同一生成的 GLSL 坐标函数；越界返回无效地址，不能钳制到其他区域。

浮点图集不需要原生 mip 链，采用对齐的非二次幂尺寸，避免刚超边界即四倍扩容。深度层级自行分区构建。逻辑日月分辨率与采集图集物理尺寸分离。

## 字段

持久世界记录为两个 RGBA16F 纹素，坐标由地址隐含，不写绝对世界位置。

| 记录 | 通道 | 语义 |
| --- | --- | --- |
| material | RGB | 线性反照率 |
| material | A | 4 位方块光和 4 位天光，整数 0–255 |
| optics | RG | 状态 ID 的两个字节，精确拆分 |
| optics | B | 发光等级与表面方向/模型旋转的有界编码，不超过 2047 |
| optics | A | 世界查询状态及有限标志；未知必须保留未知 |

材质表保存各面的 UV 高位及残差、alpha 类型、反射和吸收参数。形状表保存规范化包围盒。状态 ID、全局键、代次、布局签名均拆为不超过 255 的字节，不直接塞入半浮点大整数。

GI 保存 RGB 一阶球谐的发布、上次反弹、传播步、当前反弹和总和。光源距离图、玻璃透射、颜色传播与反射历史有独立区域。原生几何/光照 G-Buffer、水面参数、玻璃层及雨层仍分别定义语义。

## 预算

1920×1080 的初始合同（包括两个颜色银行、场景深度及日月原始采集附件）：

| 档位 | 持久图集 | 物理采集边长 | 纹理字节预算 |
| --- | --- | ---: | ---: |
| LOW | 2048×6400 | 2176 | 689.1 MiB |
| MEDIUM | 5632×4864 | 3712 | 1252.1 MiB |
| HIGH | 6656×6912 | 4736 | 1866.1 MiB |
| ULTRA | 8192×7424 | 5760 | 2502.1 MiB |

这些数字是逻辑纹理存储预算，实际驱动缓存、驻留内存和游戏峰值仍须 P11 实测。P02 驱动测试同时持有全部 23 张合同纹理，逐张检查 FBO，并执行非均匀 GPU 写入与末像素读回。进程 RSS 不作为显存指标。

布局已检查 1280×720、1920×1080 和 3840×2160 的四档共十二种组合。当前原生调度原型只验证小型固定附件；正式尺寸下的消费者和整体性能不得由小原型推断。

## 坐标

P03.1 的坐标由整数方块和局部分数组成，转换时先求整数差，再加局部浮点量。负坐标网格使用 floor 除法，所有越界地址返回无效值。四字节拆分保存整数键和代次，已在 RGBA16F 与 RGBA32F 上实际写入和读回。

J9 的 `cameraPosition` 为加载器重定位后的坐标，未暴露绝对 X/Z 偏移；`previousCameraPosition` 保留上一帧的坐标系。世界场采用带代次的加载器坐标，普通移动保留重叠区域，超过 32 格的跳变、丢帧或重载立即拒绝历史，不猜测传送对应的绝对偏移。世界场仍从本帧几何重建，后续 GI 和反射历史必须额外验证接收几何及内容代次。原生测试已覆盖正负坐标、百万坐标传送、返回和资源重载。

## 采集

P03.2 的半格近场和一格远场共享生成的分区坐标。几何阶段向每个已提交方块写观察记录，prepare 将本帧记录解析到持久世界区域。没有观察的单元写为未知，删除或卸载的方块不会沿用旧占用。部分形状在 P03.3 接入，当前记录只表示观察到了该方块。

原生测试通过四个方向的近场材质、水、玻璃、四十格远场标记以及封闭房间的四面墙。J9 不会提交尚未构建网格的区块；读回明确记录了这类区块的 `has_renderable_layers=false`、`dirty=true`。原版完成构建后，即使再次转身，阴影采集仍可取得屏外标记。未提交几何属于约定数据边界，不能把缺失记录当作空气。

## 更新

世界记录每帧由当前阴影几何重新解析，缺失几何清为未知。图集原点改变时，旧记录先按世界键重定位，再比较状态、法线、原版光照和反照率，避免把同一个纹素地址误当成同一个位置。optics.B 的低三位保留面方向，数值加八表示本帧发生变化；删除记录也保留一帧变化标记。

header 区域保存当前帧、近远场原点、快照 epoch、相机整数/分数和静态表签名。普通移动保留 epoch；跳变、丢帧及静态表变化拒绝历史。原生测试确认放置和移除后，原始几何与世界发布在同一帧改变；两个状态变化至发布样本分别约 119.55 和 113.24 ms。这仅验证世界数据发布，不代表点光阴影或 GI 的响应已经达标。

## 调试

阶段测试包提供四种视图：材质与类别、已知覆盖、更新区域、代次。左右分别显示近场和远场水平切片，紫色为未知，绿色为已有观察，橙色为本帧变化。顶部显示 epoch 的 32 个二进制位，左侧为最低位。切片高度为相机下方六格。

原生模式 3 的四张画面已逐像素与对应 GPU 读回比较；代次条、未知区域及更新闪烁均通过。模式 1、2、4 共享同一个查询入口。本阶段仍是数据生产与验证路径；完整材质、局部光、GI、反射及正式合成路径尚未迁移。

## 版本二

P04.1 使用匹配版本注册表的 1166 个方块、29671 个状态。静态定义在构建工具中生成，不读取存档，也不向目标客户端安装导出工具。构建时的 registry-api.jar 仅调整两个注册表类的字段访问级别，使独立 JVM 能执行 Forge 的注册表初始化；它不会复制到游戏实例或光影 ZIP。

每个状态改为三个 RGBA16F 纹素：形状起点、数量、旧材质类别；发光 RGB 与原版发光等级、alpha 类别；玻璃吸收与标志。形状起点用 11 位低位和 5 位高位表示，高位字段剩余六位保存扩展标志。各存储整数仍不超过 2047；未激活光源的发光 RGB 为零。

形状部件改为三个纹素，保留局部边界、旋转支点、角度和 rescale。薄片保留零厚度，单状态上限为 64 部件，整个表预留 65536 部件。963 种候选几何共使用 4745 部件。候选随机模型、模型偏移、动态模型均显式标记，其运行时判别属于 P04.2，不能把候选集合直接视为确定的实体。

为后续 UV 采集预留全部状态六面缓存和近场逐方块六面缓存。改版合同含一个 128×64×64 的静态 RGBA32F 资源，共 24 张合同纹理；原生分配测试写入了三维纹理的全部层。1920×1080 的逻辑存储预算为：

| 档位 | 版本二预算 |
| --- | ---: |
| LOW | 705.1 MiB |
| MEDIUM | 1284.1 MiB |
| HIGH | 1960.0 MiB |
| ULTRA | 2831.1 MiB |

旧合同保留在 layout，改版合同位于 layout-v2。以上均为纹理存储与分配结果，不代表显存峰值或运行帧率。新布局下的 145 个原生状态采集、完整定义表读取和表面查询已验证；524288 条射线验证了旋转、rescale、薄片和候选联合求交。材质 UV、alpha 延续和实际模型变体选择仍待后续工作包验收。

## 面与 UV

P04.2 增加逐模型面记录，保留重叠材质层、纹理名称、tint、面顶点及逻辑 UV。当前注册表产生 38968 个面、1070 张纹理和 148214 个面引用。状态到候选模型的关系仍保留，不能把所有候选都视为实际几何。

表面记录使用原静态资源的空闲区域，起点为 294912，末端为 520607，距资源尾签名尚有 3680 个纹素。所有引用在 RGBA32F 中保持精确整数。不同资源包可能超过此空间，构建器会明确失败；后续不得通过截断模型规避容量检查。

J9 的全局 `texture.noise` 绑定固定采用二维纹理目标。版本三将同样的 524288 个静态纹素改为 512×1024 的二维布局，由阴影几何、prepare 和 deferred 共享。纹理字节预算不变，仍为 24 张合同纹理，四档均已重新实际分配、写入与读回。单独阶段绑定三维纹理的原平台验证仍有效；全局三维绑定的失败记录另行保存。

原始采集取得三角面的仿射 UV，再以六个 20 位系数保存到三个 RGBA16F 纹素。无效标志独立保留；系数上界量化采用饱和处理，避免接近 2 的输入绕回 -2。模型面与纹理变换使用同一缓存，纹理记录从 180000 开始，与模型面记录分开并检查容量。

开启各向异性过滤时，J9 会按单独 sprite 绘制并提供局部 UV。采集器结合 `spriteBounds`、实际绑定纹理尺寸及 `atlasSize` 转回图集 UV；已使用图集坐标的路径不重复转换。资源重载后观察记录逐帧重建，不沿用旧图集位置。

固定模型的原生核对覆盖门、活板门、楼梯、栅栏等。关闭过滤（游戏保存为等级 1）与 4× 过滤均通过，资源重载前后准确率约 99.988%，全部轮廓失败像素计入统计，内部表面失败为零。失败的诊断附件与透明方块后续覆盖问题均保留了原始记录；最终验证在 deferred 中保存独立光栅 UV 与法线快照，避免后续玻璃、水体绘制改写参考值。

此检查点只完成固定模型的面与 UV 路径验证。随机几何、位置偏移、动态模型、重叠层 tint、alpha 延续及最终反射尚未完成；P04.2 继续保持进行中。诊断包使用额外的场景读回附件，其帧率不作为正式渲染器的性能结论。

## 双附件

J9 的阴影颜色附件固定为两个，不能按硬件的八附件上限自行增加 shadowcolor2。P04.2 的补充原生探针已验证同一阴影程序的不同附件可以分别累积和覆盖：附件零累积了 113 次贡献，附件一的 120 位有效载荷逐位保持一致，零颜色与零 alpha 也不会阻止另一附件写入。

仅声明逐附件混合会被游戏绘制状态覆盖。必须同时设置全局 `blend.shadow` 锁定状态，再对附件一关闭混合。阴影清理色声明必须放在 prepare/composite 阶段，放在 shadow 片元阶段会被 J9 忽略。失败版本及修正后的原生读回均留档。

原始记录的每个浮点通道保存 30 位数据，指数限定在 1–128，避开 NaN、无穷和次正规数。四通道可保存六个 20 位 UV 系数，另以符号位区分有效性和 tint；持久缓存仍使用三个半浮点纹素。16384 条记录的原生双通道往返测试没有位错误，打包后的真实模型场景准确率与此前一致。该路径先释放 UV 对另一阴影附件的信息占用；世界观察记录和随机模型分组尚未接入此分工，不能据此宣称迁移完成或性能提高。

## 模型选择

静态模型关系已编译为 54 种分组布局，最多包含六个独立组、20 个候选条件位和 1024 种组合。顶点及 UV 对应关系一致的面可共享记录；同一位置上的材质层顺序和重复引用数量仍保留。38968 个原始面可归并为 35687 个物理面，检查逐一核对了位置与 UV 的配对。

选择累积保存计数、一阶矩和二阶矩，只有零方差才接受某个候选，避免不同候选混入后恰好得到另一个整数结果。每组额外保留进位保护位；缺失、溢出、非整数及冲突均返回无效。65536 个原生解码测试通过，仍未用于目标实例的实际模型选择。

紫颂植物有 192 个分组实例的基础候选没有独有面。此时仅当观测到该组各候选共有且不可裁剪的面，并已证明其他候选各自存在不可裁剪的独有面，才允许用缺少额外面的证据识别基础候选。静态检查覆盖 6282 条候选路径，当前资源定义没有尚未处理的选择规则；运行时的网格提交、裁剪及更新仍待原生验证。

## 偏移

130 个原版状态使用四套离散偏移规则，各轴最多十六个取值。滴水石的水平偏移经过截断，不能用等间距公式重建。构建工具保存精确取值表，并用 133120 个未参与建表的合成位置验证；未发现表外值。此导出只执行原版的不可变偏移函数，不读取存档或正在游玩的世界，也不向目标实例安装导出 JAR。

Shader 尚未接入这些偏移表。下一步需要从实际三角面识别偏移，并以规范方块原点计算局部位置；`at_midBlock` 的字节量化不能作为精确的植物几何中心。随机模型选择、偏移、重叠层 tint 和动态模型全部验收之前，P04.2 保持进行中。


## 运行接入

当前开发合同为 v6，静态表为 512×1152 的 RGBA32F 二维资源，表面目录签名为 804。原先记录的分配验证保留为历史版本；新增布局尚未完成四档原生分配验收。

阴影附件零累积模型选择证据，附件一保存完整材质观察或 UV。新增 `far_attributes` 保存实际模型选择、离散偏移、染色和有效性。归并模型面时统一负零，重叠材质层保持合成顺序。单面不可辨认的 UV 旋转使用联合排除约束，缺少足够观察时保持未知。

光源入口已在隔离路径接入：`light_hierarchy` 保存四叉优先级树，`light_ranked` 保存候选，`light_matching` 缓存旧灯与候选的匹配，`light_previous` 固定本帧历史，`light_selection` 发布稳定槽位。各局部生产程序只绘制对应区域，并成对更新两个副本。整张世界图集仅在局部生产开始前同步一次。

材质与光源的实际截图、编译日志和剩余问题保存在 `local-docs/migration/checkpoints/P04-material-runtime/`。活动光源已驱动暖色与灵魂火把的隔离照明预览；精确灯具偏移、独立局部阴影、GI 和正式反射尚未接入，不能据此标记迁移完成。
