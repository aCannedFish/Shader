# 资源约定

## 状态

这是 P02 的资源与精度合同，消费者尚未迁移。分配和驱动验证不代表渲染功能完成。

持久图集与原始采集图集由 `tools/migration_layout.py` 生成。区域含一像素保护边界，生产者和消费者使用同一生成的 GLSL 坐标函数；越界返回无效地址，不能钳制到其他区域。

浮点图集不需要原生 mip 链，采用对齐的非二次幂尺寸，避免刚超边界即四倍扩容。深度层级自行分区构建。逻辑日月分辨率与采集图集物理尺寸分离。

## 字段

持久世界记录为两个 RGBA16F 纹素，坐标由地址隐含，不写绝对世界位置。

| 记录 | 通道 | 语义 |
| --- | --- | --- |
| material | RGB | 线性反照率 |
| material | A | 4 位方块光和 4 位天光，整数 0–255 |
| optics | RG | 状态 ID 的两个字节，精确拆分 |
| optics | B | 发光等级与表面方向/模型旋转的有界编码，不超过 2047 |
| optics | A | 世界查询状态及有限标志；未知必须保留未知 |

材质表保存各面的 UV 高位及残差、alpha 类型、反射和吸收参数。形状表保存规范化包围盒。状态 ID、全局键、代次、布局签名均拆为不超过 255 的字节，不直接塞入半浮点大整数。

GI 保存 RGB 一阶球谐的发布、上次反弹、传播步、当前反弹和总和。光源距离图、玻璃透射、颜色传播与反射历史有独立区域。原生几何/光照 G-Buffer、水面参数、玻璃层及雨层仍分别定义语义。

## 预算

1920×1080 的初始合同（包括两个颜色银行、场景深度及日月原始采集附件）：

| 档位 | 持久图集 | 物理采集边长 | 纹理字节预算 |
| --- | --- | ---: | ---: |
| LOW | 2048×6400 | 2176 | 689.1 MiB |
| MEDIUM | 5632×4864 | 3712 | 1252.1 MiB |
| HIGH | 6656×6912 | 4736 | 1866.1 MiB |
| ULTRA | 8192×7424 | 5760 | 2502.1 MiB |

这些数字是逻辑纹理存储预算，实际驱动缓存、驻留内存和游戏峰值仍须 P11 实测。P02 驱动测试同时持有全部 23 张合同纹理，逐张检查 FBO，并执行非均匀 GPU 写入与末像素读回。进程 RSS 不作为显存指标。

布局已检查 1280×720、1920×1080 和 3840×2160 的四档共十二种组合。当前原生调度原型只验证小型固定附件；正式尺寸下的消费者和整体性能不得由小原型推断。

## 坐标

P03.1 的坐标由整数方块和局部分数组成，转换时先求整数差，再加局部浮点量。负坐标网格使用 floor 除法，所有越界地址返回无效值。四字节拆分保存整数键和代次，已在 RGBA16F 与 RGBA32F 上实际写入和读回。

J9 的 `cameraPosition` 为加载器重定位后的坐标，未暴露绝对 X/Z 偏移；`previousCameraPosition` 保留上一帧的坐标系。世界场采用带代次的加载器坐标，普通移动保留重叠区域，超过 32 格的跳变、丢帧或重载立即拒绝历史，不猜测传送对应的绝对偏移。世界场仍从本帧几何重建，后续 GI 和反射历史必须额外验证接收几何及内容代次。原生测试已覆盖正负坐标、百万坐标传送、返回和资源重载。

## 采集

P03.2 的半格近场和一格远场共享生成的分区坐标。几何阶段向每个已提交方块写观察记录，prepare 将本帧记录解析到持久世界区域。没有观察的单元写为未知，删除或卸载的方块不会沿用旧占用。部分形状在 P03.3 接入，当前记录只表示观察到了该方块。

原生测试通过四个方向的近场材质、水、玻璃、四十格远场标记以及封闭房间的四面墙。J9 不会提交尚未构建网格的区块；读回明确记录了这类区块的 `has_renderable_layers=false`、`dirty=true`。原版完成构建后，即使再次转身，阴影采集仍可取得屏外标记。未提交几何属于约定数据边界，不能把缺失记录当作空气。
