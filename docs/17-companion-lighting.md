# 伴随光照

更新日期：2026-10-10。

## 实现

SimpleShader Local Lighting 为 Forge 1.21.11 提供玩家附近的方块形状、发光方块位置和材质颜色数据。它通过 OptiFine 自定义纹理接口连接光影，不依赖计算着色器或硬件光线追踪。

每个活动点光源拥有六面独立阴影图，使用普通 GPU 光栅化生成。片元按照从该光源到表面的方向选择对应的面，比较线性距离并执行四点 PCF。过滤时按接收表面的平面修正查询距离，避免掠射地面产生条纹。不同光源独立累加，太阳和月亮的可见度不会乘到火把照明上。

间接光使用带遮挡的体素辐射体积与一阶球谐方向表示。首先从局部直射和日月直射照亮的表面注入漫反射辐射，传播到相邻可通行体素；后续反弹重新收集上一反弹的入射辐射，乘以接收材质反照率和反射比例，再向空间发射。各次反弹累加后发布到供 Shader 采样的平滑三维场。更新使用双缓冲，未完成的中间结果不会被当作完整 GI 显示。

这是一套有限分辨率、有限范围的多次漫反射近似。它不等同于无限反弹路径追踪，水面镜面反射继续使用已有的屏幕反射与天空回退。方块遮挡采用 VoxelShape，部分方块可保留台阶、栅栏等轮廓；植物贴图镂空、风摆细节、活动实体和半透明材质不具有完整模型级的局部遮挡。GI 使用 Minecraft 的方块地图颜色近似反照率。

## 范围

默认体积边长为 32 方块，跟随玩家按四方块步长移动。光源照明半径上限为 16 方块，实际半径按发光等级缩放，默认最多选取 32 个影响较大的光源。范围边缘逐渐回退到原版传播场；无 Mod 或数据未准备好时也会使用原版照明。

本系统处理活动体积内的光源与遮挡，包括位于屏幕外的方块。它不会给无限距离、无限数量的火把同时建立阴影图。可按硬件能力调整体积、活动光源上限和更新预算。

## 设置

光照页面增加局部阴影和全局光照子页面。

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| 配套光照系统 | 开启 | 使用 Mod 数据和独立局部照明 |
| 独立光源阴影 | 开启 | 在表面照明中使用各光源阴影图 |
| 活动光源上限 | 32 | 最大活动点光源数量，范围 8–128 |
| 光源照明范围 | 16 | 发光等级 15 对应的最大半径 |
| 局部阴影分辨率 | 128 | 每个立方体面的分辨率 |
| 每帧阴影更新数 | 2 | 每次更新的光源数量 |
| 局部阴影柔和度 | 1.0 | PCF 采样距离 |
| 局部阴影强度 | 1.0 | 阴影与完全受光之间的混合 |
| 光照反弹次数 | 3 | 漫反射次数，0 关闭，最高 6 |
| 光照体积边长 | 32 | 求解体积的空间范围 |
| 每次反弹传播步数 | 8 | 单次反弹的空间传播预算 |
| 每帧传播预算 | 4 | 每次更新允许的传播工作量 |
| 间接光强度 | 0.7 | 表面接收 GI 的倍率 |
| 间接光反射比例 | 0.75 | 反照率之外的能量保留比例 |
| 场景更新间隔 | 0.5 秒 | 方块状态重新采集间隔 |

阴影图、场景快照和 GI 更新按预算分摊。大量光源或高反弹次数会增加收敛时间；更高更新预算可降低变化后的等待时间，同时增加帧耗时。

## 夜间

夜间环境亮度默认 0.08，月光强度默认 0.03，夜间曝光倍率默认 1.6。最低环境光按当地天光等级衰减，露天与树荫保持一定可见度，封闭洞穴仍依赖光源。这些选项位于光照页面。

## 安装

本机运行组合固定为 Minecraft 1.21.11、Forge 61.0.8 和 OptiFine HD U J9。[OptiFine 官方下载页](https://optifine.net/downloads)为 J9 列出的 Forge 版本为 61.0.8。Forge 61.2.1 与该 OptiFine 版本混用时，本机出现 `Gui.updateContextualInfo` 方法缺失，以及树叶掉落物调用 `LootModifierManager` 时资源未初始化的崩溃。

Mod 的 `pack.mcmeta` 遵循 Forge 61.0.8 官方 MDK 模板，声明格式 94.1，避免资源包与数据包使用同一份元数据时发生格式解析错误。加载、GPU 初始化、GI 发布和错误信息均写入游戏 `logs/latest.log`，方便检查实际启用状态。

```bash
python3 tools/build_companion.py
```

构建产物为 `dist/SimpleShaderLighting-0.1.0.jar`，安装到游戏实例的 `mods` 目录。首次安装或升级 Mod 后需要重新启动 Minecraft；之后修改光影设置仍可使用原有重载方式。

配套模块的源代码位于 `companion/`。默认仅对名称以 SimpleShader 开头的光影包工作，通过当前 OptiFine 的自定义纹理列表绑定两个保留纹理槽。主线程队列负责有界更新，不改变存档或服务器数据。

## 预览

固定场景增加封闭红蓝墙房间及第二光源对照。可选择部分镜头进行集成采集：

```bash
python3 tools/preview.py capture --refresh --scene lighting_gi_room --scene lighting_gi_two_lights
```

Shader 表面接收参数可离线重放。改变伴随 Mod 的光源数量、地图分辨率、体积、反弹次数及更新预算，会改变捕获的场景与 GPU 计算；这些设置加入配置校验，需要重新采集。不能仅替换 Shader 宏并声称已验证另一种反弹次数。

## 验证

在存档副本中完成了封闭红蓝墙房间的单光源与双光源对照。Mod 实际完成三次反弹更新，两个火把的照明与投影分别可见。关闭 GI 和关闭局部阴影的同帧离线对照均产生明显变化；Shader 编译检查通过 40 个入口，Mod 通过已安装 Forge API 的编译。

固定场景准备阶段另执行 96 次掉落物查询，覆盖树叶、石头和火把，直接检查此前触发崩溃的掉落物路径。检查只查询结果，不创建掉落物，也不修改正式存档。

2026-10-10 的兼容修复已验证 Forge 61.0.8 下的四个真实场景，离线重放与截图逐像素一致。最终安装包另通过未注入 apitrace 的原生启动与保存退出检查，进程退出码为 0，未出现方法缺失、掉落物管理器未初始化或资源元数据解析错误。原生验证使用与正式实例相同的 Homebrew Java 25。

捕获运行有时会被 Forge 按原版连接处理，导致存档副本的服务端文件配置被内存配置替换。预览辅助模块在副本中恢复文件配置，以保证退出时能够保存；这项处理仅属于采集工具。

正式实例路径仍为 `~/minecraft/versions/1.21.11-Forge-OptiFine/`。修复前的实例 JSON 和 Mod 保存在 `~/minecraft/backups/shader-runtime-20261010-142238/`，原依赖仍保留以便恢复。更换 Forge 或 Mod 后，应关闭 Minecraft 并重新打开 HMCL，再启动该实例。

结果保存在 `.preview/companion-validation/`，对照图为 `.preview/companion-comparison.png`。场景副本采集没有修改正式存档。
