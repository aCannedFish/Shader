# 07 · 调试、排错与性能

> 写光影的时间里有 80% 花在"为什么这里不对"。这一章是提高这 80% 效率的工具箱。

---

## 1. 最重要的一件事：调试视图

光影不能用 `printf`。你唯一能观察到的就是"屏幕上显示什么"。
所以**把中间结果画到屏幕上**是唯一有效的调试手段。

本项目的 `final.fsh` 已经内置了这个机制。改 `settings.glsl`：

```glsl
#define DEBUG_VIEW 3      // 0=关闭，1~6 见下表
```

或者游戏内 `光影设置 -> 调试 -> 调试视图`。

| 值 | 显示内容 | 用来确认什么 |
|---|---------|------------|
| 0 | 正常画面 | — |
| 1 | 视图空间法线 | 朝上=绿、朝右=红、朝向摄像机=蓝 |
| 2 | 光照贴图坐标 | 火把附近应该是红/黄，露天是绿 |
| 3 | 阴影系数 | 白=受光，黑=被遮挡 |
| 4 | 深度缓冲 | 近处黑、远处白 |
| 5 | 泛光缓冲 | 应该是模糊的光斑 |
| 6 | 视图空间坐标 | 屏幕中心偏蓝（-Z 方向） |

### 法线视图怎么读

正确的情况：

```
朝上的草方块顶面    -> 绿色 (0, 1, 0) -> 编码后 (0.5, 1.0, 0.5) = 亮绿
朝东的墙            -> 红色 (1, 0, 0) -> 编码后 (1.0, 0.5, 0.5) = 粉红
正对的石头          -> 蓝色 (0, 0, 1) -> 编码后 (0.5, 0.5, 1.0) = 浅蓝
```

如果你转动视角时**法线的颜色跟着变** —— 这是对的，
因为法线存在**视图空间**里，摄像机一转，同一个方块的视图空间法线就变了。

### 加自己的调试视图

`lib/debug.glsl` 里的 `applyDebugView()` 加一个分支就行：

```glsl
#elif DEBUG_VIEW == 7
    // 只显示水面的材质标记
    return vec3(geomBuffer.a);          // a = 材质标记
```

记得同时在 `settings.glsl` 的注释和 `shaders.properties` 的
`value.DEBUG_VIEW` 里加上 `7`。

## 2. 症状 → 原因对照表

### 画面整体问题

| 症状 | 最可能的原因 |
|------|------------|
| **全黑** | `colortex0` 没被写入（`RENDERTARGETS` 写错）；或 gamma 做了两次 |
| **全白** | 颜色被重复 gamma 编码（`pow` 做了两次）；或数值溢出成 NaN |
| **发灰发暗** | 忘了 gamma 编码（`toDisplaySpace` 没调用） |
| **颜色失真、发紫** | 有 NaN 在传播 → 检查 `normalize(0)` 和 `pow(负数, x)` |
| **噪点闪烁** | 抖动的 `frameCounter` 没取模，浮点精度丢失 |
| **画面上下/左右翻转** | 后处理用了插值的 UV 而不是 `gl_FragCoord` |
| **画面整体平移一格** | 后处理采样坐标差了半个像素 |

### 光照问题

| 症状 | 最可能的原因 |
|------|------------|
| 亮度随镜头转动闪动 | 用了视图空间的 `sunPosition.y` 判断昼夜，应该转到世界空间 |
| 背光面纯黑无细节 | 少了 `minimumAmbient` 那一项 |
| 到处都很亮 | `NdotL` 忘了 `clamp`，负值参与了运算 |
| 光照贴图不生效 | `vLightmapCoord` 传错，或光照贴图坐标没 clamp |
| 阴影里的东西和外面一样亮 | `shadow` 没乘进直射项 |
| 高光在阴影里也亮 | 高光忘了乘 `shadow` |

### 阴影问题

见 [`05-阴影映射.md`](05-阴影映射.md) 第 8 节的完整表格。

### 只看到天空、地形全部消失

**症状**：进了世界只能看到天空（或纯色背景），方块、生物全都不见了，
但游戏本身没崩。

**原因**：`gbuffers_terrain` 等程序编译失败。OptiFine 编译失败时不会退出，
它会让这个程序失效，于是所有地形都不画了 —— 只剩下天空（天空是
`gbuffers_skybasic` 画的，那个程序没出错）。

**排查**：翻日志找 `Error compiling` / `Error linking program`：

```bash
grep -i "error compiling\|error linking" ~/minecraft/versions/*/logs/latest.log
```

本项目踩过一次这个坑，值得单独记住：

```
ERROR: 1:57: Use of undeclared identifier 'RGBA16F'
[Shaders] Error linking program: composite1
[Shaders] Error: Invalid program "final"
```

`const int colortex0Format = RGBA16F;` 这种写法是 **OptiFine 专有语法，
不是合法 GLSL**。OptiFine 读得到它，但**不会把它从源码里删掉**，
于是 GLSL 编译器看到 `RGBA16F` 这个没定义的标识符，直接报错。

正确写法是把它**包进块注释**（见 `settings.glsl` 里的说明）：
OptiFine 按行扫原始文本，注释里的内容它照读不误；
GLSL 编译器则直接把整段当注释忽略。两边都满足。

```glsl
/*
const int colortex0Format = RGBA16F;
*/

const bool colortex0Clear = true;   // 这个不用注释，true 是合法 GLSL 关键字
```

⚠️ 注释块里的行首**不能加 `*`**（写成 ` * const int ...` 就匹配不到了），
必须是裸的 `const` 开头。Iris 的 `ConstDirectiveParser` 也是同样的规则。

### 整个世界变透明，只剩生物和粒子

**症状**：地形（方块、地面）全都不见了，世界像被掏空一样能看穿；
但怪物、掉落物、粒子这类"实体"还正常显示。

**可能原因之一**：顶点颜色的 alpha 通道。

部分地形渲染路径可能给出接近 0 的顶点 alpha。
如果片元着色器里直接写：

```glsl
vec4 albedo = texture2D(texture, vTexCoord) * vColor;   // albedo.a = 0
if (albedo.a < alphaTestRef) discard;                   // 0 < 0.1，全丢
```

这些地形像素会在 alpha 测试时被 `discard`，连深度都不写。
但“只剩实体”也可能由顶点位置错误造成，不能仅凭症状认定是 alpha。

**正确写法**（`lib/vertex_transform.glsl` 已经这么做了）：

```glsl
vColor = color;
if (vColor.a < 0.1) {
    vColor.a = 1.0;      // 只把"接近 0"的归一，真正的半透明保留
}
```

注意是"小于 0.1 才归一到 1"，不能无脑 `vColor.a = 1.0`：
粒子的淡出效果靠的就是 0.1~1.0 之间的 alpha 值。
若画面出现贴图被拉成一团或随视角移动，优先检查顶点空间。
地形的 `gl_Vertex` 位于模型空间，应使用 `gl_ModelViewMatrix` 变换；
只乘 `gbufferModelView` 会丢掉区块偏移。

### 天空与雾

如果日出或日落时地平线附近的地形变黑、偏灰，而天空仍有颜色，
先检查 `fogColor` 的声明。OptiFine 提供的是 `vec3`；声明成 `vec4`
会在设置 uniform 时触发 OpenGL 1282，着色器拿不到正确的地平线颜色。
旧版项目正有这个错误，现已在 `lib/uniforms.glsl` 修正。

天空顶点色与 `fogColor` 都由游戏按显示颜色提供。它们在进入 HDR
缓冲区前应采用相同的显示空间到线性空间转换，最后由 `final.fsh`
统一映射。太阳和月亮方向也不能直接插值，两者相反时会互相抵消。

天空程序还必须按图层设置混合方式。`gbuffers_skybasic` 会画日落光晕和
地平线层，应保留顶点 alpha 并进行 alpha 混合。原版太阳、月亮贴图是
不透明黑底，`gbuffers_skytextured` 应使用加法混合；按普通 alpha 混合
会在太阳周围露出黑色方框。

天空穹顶与地平线属于不同几何层，直接照搬各层顶点色会在视线附近
形成过高的水平色带。基础天空改为根据视线在世界空间的仰角，
平滑混合 `fogColor` 与 `skyColor`；带硬边的原版日落扇面被跳过，
星星仍保留原版顶点色。
水下的天空背景使用水下雾色，避免远景穿出亮蓝色天空。

### 阴影与云

日志中 `usedShadowDepthBuffers: 0` 表示没有程序使用阴影深度贴图。
采样器必须使用加载器识别的 `shadowtex0`；自定义名字 `shadowMap`
虽然能通过 GLSL 编译，却不会自动绑定。云程序也要对应顶点格式：
当前原版云只提供位置、颜色和法线，不能依赖地形图集坐标或光照贴图坐标。

### 水面 / 半透明问题

| 症状 | 最可能的原因 |
|------|------------|
| 水面完全不透明 | `writeGBuffers` 的最后参数没传 `albedo.a` |
| 水面闪烁 | 波浪位移过大导致 Z-fighting（调小 `WAVE_AMPLITUDE`） |
| 水面波浪按区块重复 | 波浪相位直接用了 `gl_Vertex`，应先转换到绝对世界坐标 |
| 玻璃后面的东西消失 | `discard` 把半透明像素丢掉了（检查 `alphaTestRef`） |
| 水下远处出现黑色水面片 | 水面底部背光或自阴影；只给顶面做波浪，并检查水下散射光 |

## 3. 编译错误怎么读

光影编译失败时，游戏日志（`minecraft/logs/latest.log`）里会有：

```
[Shaders] Error compiling fragment shader: shaders/gbuffers_terrain.fsh
0:123(5): error: `undeclaredIdentifier' undeclared
0:145(12): error: cannot convert from `vec3' to `vec4'
```

读法：

```
0:123(5)    行号 123，第 5 个字符
error: ...  具体错误
```

⚠️ **行号是"展开 #include 之后"的行号**，和你文件里的行号对不上。
两个办法：

1. **看错误信息里的标识符名**，直接在项目里全局搜索它
   （`grep -rn "undeclaredIdentifier" shaders/`），立刻定位到是哪个文件
2. 临时把 `#include` 换成文件内容，得到准确行号

### 常见错误对照

| 错误信息 | 原因 |
|---------|------|
| `undeclared identifier` | 变量名拼错；或忘了 `#include` 对应的 lib |
| `cannot convert from vec3 to vec4` | 少写了 `vec4(x, 1.0)` 或 `.rgb` |
| `no matching overloaded function` | 参数类型不对，常见于 `texture2D` 传了 vec3 |
| `redefinition of ...` | 同一个 uniform 声明了两次（检查所有 `#include`） |
| `varying ... not declared` | `.vsh` 和 `.fsh` 的 varying 不一致 |
| `constant expression required` | GLSL 120 的循环上界必须是常量 |
| `array size must be constant` | 同上，数组大小必须是常量 |

## 4. 在本机测试

你的环境（已经配置好）：

- 启动器：HMCL
- 实例目录：`~/minecraft`，版本 `1.21.11-Forge-OptiFine`
- **光影目录**：`~/minecraft/versions/1.21.11-Forge-OptiFine/shaderpacks/`

⚠️ **这台机器开了版本隔离**。开了隔离之后，游戏读取的是
`versions/<版本名>/` 下面的 `shaderpacks`、`saves`、`mods` 等，
而不是 `~/minecraft/` 根目录下的。**光影放错位置就完全看不到**
（列表里不会出现，也不会报错）—— 这是本项目第一次没加载出来的原因。

### 使用步骤

1. 启动 HMCL，运行 `1.21.11-Forge-OptiFine`
2. 改完代码后同步（脚本会自动同步到所有可能的位置）：
   ```bash
   bash tools/deploy.sh
   ```
3. 游戏内按 `F3 + R` 重载光影（一秒生效，比重启游戏快得多）
4. 改 `settings.glsl` 里的参数则**不需要重载**

> 为什么用拷贝而不是软链接？Java 列目录时对符号链接的处理在不同启动器
> 版本上并不一致，实测这台机器上软链接不出现在光影列表里。
> `tools/deploy.sh` 用 `rsync` 做增量同步，代价可以忽略。

### 前置检查

光影**必须**通过 OptiFine 或 Iris 加载。进游戏后：

- 如果 `视频设置` 里没有 `光影` 按钮 -> OptiFine 没装好
- 如果列表里看不到 `SimpleShader` -> 目录结构不对
  （必须是 `shaderpacks/SimpleShader/shaders/...`）

### 看日志

```bash
tail -f ~/minecraft/logs/latest.log | grep -i shader
```

编译错误、警告都会在这里出现。

### 离线编译检查

本项目已经用 `glslangValidator` 做过全量静态检查（32 个程序全部通过），
改完代码也可以自己跑一遍，不用启动游戏就能发现语法和类型错误：

```bash
python3 tools/check_glsl.py
```

输出形如：

```
OK   gbuffers_terrain.fsh
OK   gbuffers_terrain.vsh
...
通过 32 / 32
```

脚本做的事：把 `#include` 递归展开成单个文件，补上 OptiFine 专有的
`RGBA16F` 之类的格式宏定义，再喂给 `glslangValidator`。
安装校验器：`brew install glslang`（Ubuntu：`apt install glslang-tools`）。

⚠️ 静态检查**查不出**逻辑错误（坐标搞反、参数取错），
那些只能靠进游戏 + 调试视图。

### 常见加载失败原因

| 现象 | 原因 |
|-----|------|
| 光影列表里看不到 | 目录结构不对（必须是 `shaderpacks/名字/shaders/...`） |
| 选中后画面全黑 | 大概率是 `#version` 不是第一行，或有编译错误 |
| 选中后闪一下回到原版 | 编译失败，OptiFine 会自动回退到原版渲染 |
| 选项界面空白 | `shaders.properties` 语法错误 |

## 5. 性能

### 先建立正确的心态

光影的性能瓶颈**几乎总是填充率（像素数），不是顶点数**。
片元着色器每帧跑几亿次，所以：

- 片元着色器里省一次纹理采样 > 顶点着色器里省十次矩阵乘法
- 减少采样次数（阴影 PCF、泛光模糊）是最有效的优化

### 什么时候该担心

| 情况 | 判断 |
|------|------|
| 关掉光影后帧率翻倍以上 | 正常，说明光影有开销但不离谱 |
| 分辨率减半帧率翻倍 | 正常的填充率瓶颈 |
| 改小 `shadowMapResolution` 后帧率大幅提升 | 阴影是瓶颈 |
| 附近没水时帧率也不高 | 泛光的模糊是全屏的，代价固定 |

### 本项目已经用了的优化

| 手段 | 位置 |
|------|------|
| 宏裁剪：关掉的功能完全不编译 | `ENABLE_SHADOWS`、`ENABLE_BLOOM` 等 |
| 距离淡出：远处不采样阴影 | `lib/shadow.glsl` |
| 只输出必要的数据 | `colortex1/2` 用 RGBA8 而不是浮点 |
| 先 alpha 测试再算光照 | 所有 gbuffers 的 fsh |
| 天空/云不做阴影计算 | `gbuffers_skybasic`、`gbuffers_clouds` |

### 还可以优化什么

**① 阴影采样次数**

```glsl
#define SHADOW_SOFTNESS 1    // 9 次采样，降到 0 就是 1 次
```

**② 泛光模糊**

当前的 5×5 = 25 次采样。改成可分离的两次一维模糊：

```glsl
// 第一次只沿水平方向采 5 个点，第二次只沿垂直方向采 5 个点
// 采样数从 25 降到 10，效果几乎一样
float weight = exp(-float(offset*offset) / twoSigmaSq);
```

代价是需要多一个 colortex 做中间结果（本项目已经用了 4 张，
`colortex5` 还空着）。

**③ 降低远处精度**

```glsl
// 距离超过 32 格的整体改用简化光照
if (viewDistance > 32.0) {
    color = albedo.rgb * lmColor;    // 不采样阴影
} else {
    color = computeLighting(...);
}
```

**④ 分辨率缩放**

`settings.glsl` 里可以加：

```glsl
const int shadowMapResolution = 1024;   // 从 2048 降下来
```

或者在 `shaders.properties` 里用 `scale.composite = 0.5` 让后处理
在半个分辨率上跑（泛光本来就模糊，看不出来）。

### 测量方法

按 `F3` 看帧率，然后**一次只改一个参数**，记录帧率变化。
没有基准数据的优化都是瞎猜。

## 6. 开发纪律（很重要）

1. **一次只改一个变量**。改五个参数后画面变了，你不知道是哪个起的作用。
2. **改完先看调试视图**，确认数据本身对了再看最终画面。
3. **保留能跑通的版本**。改坏了就退回去，别在坏掉的版本上继续改。
4. **不确定就打印**。把某个值直接 `gl_FragData[0] = vec4(value);` 输出，
   比盯着代码猜快得多。
5. **读别人的光影**。遇到不懂的效果，去 GitHub 找成熟光影的对应文件，
   搜索关键字（`#define` 名、函数名），通常能直接找到实现。
