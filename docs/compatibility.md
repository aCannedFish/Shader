# 兼容

## 基线

| 项目 | 验证基线 |
| --- | --- |
| Minecraft | Java Edition 1.21.11 |
| 加载器 | OptiFine HD U J9 |
| Forge | 61.0.8，配套 Mod 使用该版本编译并验证 |
| Java | 编译目标 21，实际运行验证为 Oracle/Homebrew Java 25 |
| 平台 | Apple M3、macOS、Apple OpenGL 4.1 |
| 场景 | 主世界、下界、末地；日夜、水体、材质、局部光照及植被固定场景 |

已验证组合不代表每一种硬件、世界、资源包或设置组合均已覆盖。

## 加载器

基础 Shader 采用 OptiFine 风格的程序名称、属性和 uniform。Iris/Sodium、Fabric 和其他 OptiFine 版本尚未完成专项验证，0.2.2 不承诺其兼容性。配套 Mod 为 Forge 客户端模块，直接使用 OptiFine 纹理和设置接口，不适用于 Iris 或 Fabric。

Forge 61.2.1 与 J9 混用时在本机出现过 `Gui.updateContextualInfo` 缺失和 `LootModifierManager` 未初始化的崩溃。使用 [OptiFine 官方列出的 Forge 61.0.8](https://optifine.net/downloads)。

## 图形接口

Shader 入口为 GLSL 120，实际程序由 OptiFine 进行兼容转换。局部阴影与 GI 使用 GLSL 330、浮点纹理、VAO、FBO 和普通光栅化。

管线使用最多八个颜色附件。Mod 额外使用纹理单元 12、14，天空噪声使用单元 15。不能依据源文件的 `#version 120` 推断整个系统能在旧 OpenGL 2.x 硬件上运行。当前确认的图形基线为 OpenGL 4.1；其他满足接口能力的平台仍需实测。

## 渲染倍率

0.2.0 修复了 OptiFine「视频设置 → 光影 → 渲染精细度」不为 1 倍时的画面裁切与错位。`viewWidth/Height` 表示内部场景纹理尺寸，最终输出阶段的视口则是窗口尺寸；此前用前者归一化后者的像素坐标，导致采样 UV 随倍率错误缩放。

现在 `final.vsh` 传递全屏四边形的归一化 UV，`final.fsh` 用它读取场景、泛光与调试缓冲区。内部半分辨率体积场、天空缓存和首像素元数据继续按内部尺寸定位。这项修复不新增光影选项，也不修改玩家选定的渲染倍率。

实机回归采用菜单相同的程序重载与缓冲区重建路径，覆盖 0.5、2/3、0.75、1、7/6、1.5、2 倍、恢复 1 倍，以及水下 0.5／2 倍，共十个镜头。输出尺寸固定为 1922×1078，包含内部 1281×719 等取整情况；固定立柱边缘的位置差不超过 2 个输出像素，十个原生画面与 GPU 重放逐像素一致。2026-10-16 收尾时本地 `.preview` 目录被删除，图像和报告不再可用，补充 UV 探针与旧公式对照未完成；上述已完成的回归结果不包含这组补充测试。

## 限制

- 日常离线预览工具目前支持并验证 Apple Silicon macOS。它需要先运行真实客户端采集场景，之后以相同渲染调用离线重放。
- 水面 SSR 和折射使用单层屏幕深度，视角外及遮挡后的几何无法完整重建；缺失反射使用天空回退。
- GI 与玻璃透射缓存覆盖有限的相机周围体积；独立点光阴影围绕选中的光源采集遮挡，受活动数量与半径预算限制。未被选中的光源保留原版光照传播。
- 局部求解不包含活动实体、手持光源模型、植物贴图镂空和完整透明材质遮挡；风摆与日月阴影匹配，局部遮挡使用方块形状近似。
- 0.2.0 增加了染色玻璃与玻璃板的 RGB 透射；点光源和 GI 的透射缓存依赖同版 Mod，受局部快照范围限制。日月表面阴影使用最近一层投影体的透射色，不能还原多层玻璃的逐层吸收。其他透明材质与玻璃折射焦散仍未完整求解。
- GI 是漫反射体素近似，不包含无限反弹、镜面多次反弹或完整路径追踪。
- 自定义维度、特殊天气、PBR 资源包、Distant Horizons 与其他渲染 Mod 尚未完成专项验证。主世界、下界和末地使用各自的环境入口。

## 发布验证

0.2.1 发布检查覆盖默认、四档预设及关闭功能的共 7 组配置，每组 44 个 Shader 入口，共 308 次编译；另检查 8 个配套 GPU 程序阶段、Java 21 目标构建、91 项配置一致性和发布附件。Mod 运行代码与 0.2.0 相同，两个版本可配套使用。

0.2.1 已重新捕获真实客户端场景并逐像素核对离线重放，覆盖天空、水面、水下、植被逆光及遮挡；正式默认设置下另确认配套阴影与三次漫反射 GI 正常发布。体积分辨率检查包括 2/3 渲染倍率下的奇数内部尺寸及恢复 1 倍渲染，天空接缝、泛光边界和风摆同步另有 GPU 探针验证。

性能数值来自 Apple M3 上的独立通道测量，不能直接换算为整机帧率提升；其他平台与未覆盖场景仍需实测。

## 0.2.2

0.2.2 的材质、维度、氛围与矿物实现通过三维度共 132 个入口的检查，默认、四档预设及关闭功能的 7 组配置共 924 次编译，另有 8 个配套 GPU 程序阶段、Java 21 目标构建和 108 项配置校验。

本轮 15 个真实客户端镜头覆盖森林晨昏、正午、夜间、山坡、晴雨极光、水面天空、下界、末地、矿石暗室、玻璃及水下。十五幅原生截图与当前源码 GPU 重放逐像素一致。关闭新增效果后的同帧对照确认矿物发光与氛围有效，水下镜头的差异为零；这一结果限于所测镜头，不代表所有水下地形和时间均已覆盖。

地表 GPU 读回确认树冠下高度、森林权重和天空光正确。矿物 GPU 遮罩与资源包生成的 CPU 字节完全一致，十八种矿物的像素覆盖约 13%–34%；单独 GLSL 探针检验 73,728 个矿物/石头样本，未出现石头像素额外自发光。另检查旧 Mod 回退、强度、UV 精度、雾透射上限、介质合并、极光运动/冻结/计时回绕、雨天衰减及维度隔离。

此前材质验证包含昼夜、玻璃、铜箱、下界/末地与水体；GPU 约束检查覆盖 RGBA8 法线完整球面、材质字节存储、GGX 互易性、背向光源截止与 Fresnel 掠射极限。所有运行结果仍限于本机已验证平台；自定义资源包、硬件和复杂地形需要另行检查。新效果增加了 GPU 工作量，当前没有整机帧率收益或开销的普适结论。

配套 Mod 的实际渲染帧调度、遮挡验证、快照与上传缓存另通过原生静止、移动、动态编辑、角落和染色玻璃回归。固定 40³ 区域的体素、吸收和网格字节一致；仅 CPU 采集阶段的分配与耗时下降，整体帧率没有稳定提升结论，测量范围见[性能说明](performance.md)。
