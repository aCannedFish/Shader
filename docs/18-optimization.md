# 优化记录

本轮基于 `195dd79`，只调整现有水体、天空、阴影和光照模块。参考范围为本机安装的 BSL、Complementary、Sildur 源码；未移植它们的配色、材质风格或整套渲染代码。

## 开销来源

水面附近的额外开销主要集中在反射与水下合成。反射强度只影响合成权重；除非为零，降低强度通常不会缩短追踪过程。原实现每个水面像素最多进行 96 次屏幕空间深度步进，并在屏幕反射完全覆盖时仍计算天空与云的后备反射。水下另有每像素九点入水深度估计，包含位置重建和矩阵运算。

伴随 Mod 的开销也不能忽略。默认最多 32 个局部光源，每个光源有六面阴影，另有 32³ 体素的三次间接光传播。这些工作与主光影的水面追踪叠加。原桥接代码在每次调度时遍历并切换所有光影程序，即使场景与 GI 绑定参数没有变化。

## 水体改动

| 项目 | 原实现 | 当前实现 |
|---|---|---|
| 波浪法线 | 四次高度计算，共 12 次动态正弦 | 用正弦差恒等式计算同一中心差分，三次动态余弦 |
| 反射步进 | 最多 96 步 | 最多 64 步，调整步幅以保留最长屏幕追踪距离 |
| 命中精修 | 五次精修 | 保留，复用命中深度与位置 |
| 粗糙反射 | 九点过滤 | 保留 |
| 云反射 | 16 次云步进 | 保留；屏幕反射完全覆盖时跳过环境反射 |
| 水面高光 | 几何与合成阶段重复计算 | 只保留最终合成阶段的高光 |
| 入水深度 | 每个水下像素九点估计 | 每帧估计一次，每个像素读取一个纹素 |
| 洞穴水面 | 即使无直射天光仍查询阴影 | 直射天光可见度为零时跳过方向光和云阴影查询 |

入水深度复用水下不显示的云缓冲首个纹素，没有新增附件。保留折射方向、全反射、吸收和水下空气景物的深度校验。尝试过进一步缩减反射步数、云反射精度与低 Fresnel 区域的环境反射，但画面损失或收益不稳定，最终未采用。

## 天空修正

天顶与天底的小聚焦点来自球面 LUT 的极点处理：采样行没有覆盖真正的纬度端点，而且向下方向在水平分量接近零时，被原有高度限制归一化成向上方向。

当前 LUT 覆盖真正的纬度端点，天顶取同一方向，天底取四个固定方向的平均值，并将端点映射到纹素中心。低于地平线的射线先稳定水平朝向，再约束高度。两种垂直视角的实际游戏截图中，中心的尖锐聚焦点已消失。

## 阴影修正

原实现先在顶点上做径向畸变，再插值到片元。非线性畸变的插值结果不等于实际接收点的投影，尤其容易在掠射光下产生位置误差。当前传递未畸变坐标，在片元阶段统一除以 w、施加畸变和采样。

方向光改为有限采样的 PCSS 近似，执行遮挡搜索、平均深度估计、半影宽度计算和 PCF 过滤，遵循 [NVIDIA PCSS 白皮书](https://developer.download.nvidia.com/assets/gamedev/docs/PCSS_Integration.pdf) 的基本流程。方向光为正交投影，深度差直接换算为沿光线的世界距离，用太阳角半径估计软度。

默认档使用五点遮挡搜索与八点过滤，无遮挡时提前返回；高档为九点搜索与十二点过滤。默认档完全受光处的读取数从九次降到五次，有遮挡处最多十三次。软阴影改善真实性，同时增加部分像素的开销，不能将所有阴影区域都视为性能提升。

自阴影处理采用接收面深度梯度补偿，并保留受限的基础偏移。取消掠射角下八倍偏移，避免阴影悬离物体底部。正午、日出和日落的固定场景已检查底部接触与表面条纹。直射日光、月光的渐入条件也改为与实际光源所在半球一致，环境暮光过渡保留。

局部点光仍使用四点过滤，改成相邻深度比较结果的双线性权重，并保留接收面补偿。这改善了纹素阶梯，但没有把点光升级为完整 PCSS。真实的树冠内部遮挡仍保留；需要避免的是由精度误差产生的条纹自阴影。

## 局部光照

方块光默认强度从 2.0 调整为 1.0，Shader 与 Mod 的默认值同步，减轻光源过曝。体素照明边界的渐变从三格扩展到六格，缓和局部体积切换处的边缘。体积之外跳过局部直射与间接光查询。

伴随 Mod 记录场景与 GI 发布版本，仅在参数更新、GPU 资源更换或光影重载时重新绑定全部程序；每 250 ms 检查一次纹理提供器是否被重载替换。纹理提供器继续为每个绘制通道提供当前的 ping-pong 纹理，没有降低 GI 反弹次数或局部阴影更新预算。

## 验证结果

- GLSL 语法与类型检查通过 40/40 个程序。
- 配置检查通过 74 个参数、11 个页面；伴随 Mod 构建成功。
- 在隔离的世界副本中重新启动 Minecraft，采集并回放 13 个固定场景，覆盖水面、洞穴水体、水下、天顶、天底、局部光照，以及正午、日出、日落阴影。
- 法线恒等式的双精度数值对照最大误差约为 5×10⁻¹⁵；GPU 结果存在正常的浮点舍入差异。
- 单独核对水体性能修改、尚未合入后续光照调整时，五个水体场景的全画面平均颜色差为 0.0039～0.0160/255。
- 将水下缓存恢复为每像素重新估计，其他代码保持一致，两场景平均颜色差为 0.000289 与 0.001234/255。缓存的半浮点存储存在微小量化误差。

帧率测量使用本机 M3，逻辑窗口 960×540、实际渲染 1920×1080、六区块视距、关闭 VSync、帧率上限 260。每次重新启动客户端，场景等待八秒后采样十秒，每 0.5 秒读取游戏显示 FPS；FPS 本身约每秒刷新，因此这些不是独立的逐帧时间样本，最小值也不是 1% low。

首轮按用户原有 Smooth FPS 设置测量，水面两次中位数为 39→38、29.5→29，最小读数为 18→26、18→27。白天与水下波动更大，无法从这些数字得出稳定的提升百分比。GPU timer 查询在本机回放中出现负值，未用于结论。

再关闭 OptiFine 的 Smooth FPS，按旧版、新版、旧版、新版顺序完成另一组测量。显示 FPS 中位数如下：

| 场景 | 旧版一 | 新版一 | 旧版二 | 新版二 |
|---|---|---|---|---|
| 白天 | 56 | 53 | 31.5 | 37 |
| 水面 | 43.5 | 40 | 21 | 29 |
| 水下 | 29 | 29 | 28 | 29 |

旧版自身存在较大跨次漂移，第一组和第二组变化方向也不一致，当前数据不能确认稳定的整机 FPS 增益，也不能排除个别场景变慢。已减少的采样与绑定工作属于代码开销的改进，实际收益仍受 GI 更新、方向光过滤和设备状态影响。水下入水估计减少很多，但此测试中的总 FPS 几乎不变，说明其收益可能被其他阶段掩盖。

完整采样与环境记录见 [测试数据](benchmarks/2026-10-14.json)。这些测试不构成 1% low 或 M3 Max 性能结论。

## 参考差距

本地源码显示，BSL 与 Complementary 的反射实现采用自适应步进，并仅在屏幕反射不足时计算后备颜色。它们的阴影采样预算较小；部分配置利用 TAA 将更少的每帧采样积累成平滑结果。Sildur 的一段半影实现受 NVIDIA/Windows 条件限制，不能直接用于本机 Mac。不同包的默认预设、材质规则和平台分支差异较大，本轮没有进行它们与 SimpleShader 的同配置 FPS 排名。

| 模块 | 当前差距 |
|---|---|
| 时间积累 | 缺少 TAA、反射历史复用与时间降噪。云、反射和阴影需要较多当前帧采样，宽半影仍可能有细小阶梯。 |
| 水面反射 | SSR 仍依赖当前屏幕，屏外与被遮挡物体只能用环境反射补足；缺少分层深度加速和反射历史稳定。 |
| 材质 | 缺少完整 labPBR 材质流程，金属、材质法线、视差与不同植被的透射规则不够完善。参考包提供的具体选项有所不同。 |
| 光照平衡 | 当前局部阴影与多次体素 GI 有实际成本，但体素空间范围有限，仍可能出现漏光、体积更新或低分辨率边界。材质反射率与曝光的整体校准也不够成熟。 |
| 软阴影 | 当前方向光使用有限范围 PCSS 近似，远距离宽半影可能估计不足；点光尚无遮挡距离决定的接触硬化。 |
| 水下折射 | 单层屏幕深度无法完整描述多层透明界面，屏外景物与复杂水线附近仍可能退回环境近似。 |
| 环境效果 | 缺少完善的雨天湿润反射、水下焦散和体积光束。这些未在本轮添加。 |
| 平台适配 | 尚未建立覆盖不同显卡、加载器与分辨率的持续性能基准，当前验证主要针对 Mac 的 Forge/OptiFine。 |

因此，SimpleShader 目前的主要差距集中在时间复用、材质规则、光照校准和资源调度。局部阴影与三次 GI 的计算量较大，但画面仍受粗体素、SSR 屏幕信息和简单材质限制。继续单纯提高采样数会更贵，也不一定能改善这些限制。

## 源码位置

SimpleShader 的主要改动：`shaders/lib/water.glsl`、`water_reflection.glsl`、`shadow_filter.glsl`、`sky.glsl`、`companion_lighting.glsl`，以及伴随 Mod 的 `LightingBridge.java`。测试画面保存在 `.preview/game/screenshots/`，测试输出位于 `.preview/`，该目录不提交到 Git。

参考路径以本机版本目录 `~/minecraft/versions/1.21.11-Forge-OptiFine/shaderpacks/` 为根：

- BSL：`shaders/lib/lighting/shadows.glsl`、`shaders/lib/reflections/raytrace.glsl`、`shaders/lib/settings.glsl`。
- Complementary：`shaders/lib/lighting/shadowSampling.glsl`、`shaders/lib/materials/materialMethods/translucentReflections.glsl`。
- Sildur：`shaders/composite.fsh` 及其设置文件，重点查看半影的平台条件与反射预算。

## 使用方式

游戏目录需同时更新光影文件和 `SimpleShaderLighting-0.1.2.jar`。Mod 的绑定优化需要完整重启客户端，单独 F3+R 无法载入新的 Java 类。已保存的 `BLOCK_LIGHT_STRENGTH` 会覆盖新的默认值；若其他设备保留旧值 2.0，需要将它调为 1.0 才能获得本轮的亮度校准。
